# 修复液态玻璃的高光精度与跟随延迟

## 确认的问题

静态44px按钮原本固定1×，含padding的两张材质图仅48×48；恢复显示比例策略后2×以上设备应为96×96。旧40帧滚动诊断约14505次rect读取、5117次computed style读取、0材质GPU回读，问题不能统一归为每帧PNG编码。封面、按钮与光学各自调度，存在旧帧采样和重复draw。

## 实施

1. 静态按钮/底栏/菜单端点使用min(devicePixelRatio,2)；中间形状保留原库DPR，缓存键包含实际DPR，保留shader与独立裁切。
2. 所有刷新入口合并至一套frame phases：推进封面/控件本帧状态，读取一次冻结背景快照，投影各镜片，批量写入光学。多个镜片共享rect、computed styles、节点分类及inline快照。
3. 保持局部有界采样、每lens限制；缓存本地clip polygon，纯平移不重新拼接，mask/style/子节点只在变化时写。不得恢复foreignObject或泄漏矩形副本。
4. 从已核验Glass-HQ/广彩参考移植Worker编码、解码Image保活、活跃maps pin和受限缓存；常用静态形状及变形路径提前准备。Worker失败时分片主线程编码并复用缓存，不集中阻塞一次点击。
5. 保留真实折射、Liquid Gooey、连续跟手退出、独立收藏与稍后阅读，不将Safari全站改磨砂。

## 验收

分别测冷启动、重复菜单、滚动、主题变化，诊断只在测试开关中启用。DPR1/2/3贴图尺寸可核验；同帧只有一份文章背景快照，稳定滚动没有材质生成。复验黑字/蓝链经过底栏、停住/反向和Safari地址栏收放。单元、类型、内容、构建、导出及已有交互回归通过后交付4337和独立Netlify draft。

在既有PR #143追加原子提交，正式站保持不变；iPhone确认清晰和无明显追赶后才提升。若真实合成仍跨多帧拖尾，保留测试版本并重新评估滚动合成路径，不能标记为解决。
