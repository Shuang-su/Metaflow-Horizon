## SplatTransform 将 SOG v3 设为默认输出

SplatTransform 是把高斯扫描转换、压缩为不同交付格式的命令行工具。11 月 9 日合并的改动将普通 SOG 输出默认切到 v3，让文件除了画面数据，还能携带逐点标签、特征向量等自定义属性。这对语义选择、编辑和自定义渲染有用，但现有查看器未必认识新文件。

维护网站或转换服务的团队，需要一起核对写入器与读取器。仍要兼容旧查看器时，可以显式使用 `--sog-version 2`，并保留原始资产；退回 v2 不能完整保留 v3 新增的属性与表示能力。按本期合并状态，HTML 导出仍嵌入 v2，不能由普通 SOG 的默认版本推断 HTML 已同步升级。

这条记录对应已合并代码，当期尚未核实整套工具的新稳定发行。可先对一份含透明度和视角相关颜色的资产转换、打开、再导出，确认所需属性没有丢失，再决定是否批量切换。

:::details[新增表示与当期编码细节]

v3 支持四阶球谐、逐高斯带类型扩展字段、场景附加信息，以及可大于 1 的线性不透明度。该次实现以旋转编码放入纹理 alpha 通道；这是 11 月 10 日的历史状态，后续布局修订见 11 月 13 日。转换到只能表示标准不透明度的格式时会截断超过 1 的值，不能把格式转换视为无损保存所有语义。

:::

[来源](https://github.com/playcanvas/splat-transform/pull/370)

## SPZ v4 增加可跳过的逐点属性块

SPZ 是用于压缩和交换高斯场景的文件格式。此次 v4 扩展在核心场景数据之后增加具名逐点属性，可用于法线、材质信息或语义特征，让需要这些数据的应用不必另行维护一份对应表。

它没有更换版本号：不认识扩展的旧 v4 读取器可以跳过额外数据，继续打开核心场景。但“能打开”不等于“保留扩展”；若中途经过不支持扩展的转换器或编辑器，重新导出时可能丢掉这些属性。需要属性的团队应使用启用扩展支持的构建，并检查读取、保存、再打开的完整链路。

本次为 11 月 9 日合并的实现，提供 C++、Python 与 JS/WASM 接口。作者验证了旧读取端的核心输出兼容性；各编译器、Android 与浏览器环境的完整矩阵仍需下游确认。

:::details[扩展帧与作者性能口径]

附加数据使用 zstd 可跳过帧，属性可为 32 位或 1—8 位量化。作者比较不同分帧大小时报告压缩率接近、保存时间和峰值内存降低；这些是指定条件下的结果，不代表新增了完整随机访问或渐进流式协议。

:::

[来源](https://github.com/nianticlabs/spz/pull/107)

Blender 5.3 可从 PLY、SPZ、USD 和 glTF 导入高斯，并在 Workbench、EEVEE、Cycles 中渲染。用户可以在熟悉的三维创作环境里安排扫描与其他对象；这一版本尚不支持原生高斯导出，不能据此认为格式往返已经完整。

## SuperSplat 与转换器改善大场景 SOG 导出稳定性

SuperSplat 的浏览器编辑器现在能在压缩用 GPU 设备丢失后清理缓存，并提示重新尝试；SplatTransform 则拆小一次提交的压缩工作，降低 macOS 因长时间 GPU 工作而中止任务的风险。

这两项分别处理失败后的恢复和触发失败的工作量。对在 Mac 上导出大场景的用户，主要价值是更可靠地完成交付；作者的速度对比只覆盖指定设备与场景，不是普遍的大幅加速。

:::details[发布内容与使用条件]

- **一手来源**：[SuperSplat PR #1094](https://github.com/playcanvas/supersplat/pull/1094) / [`c061d0d`](https://github.com/playcanvas/supersplat/commit/c061d0d6a56c730487f90e7683eee09422864e56)、[SplatTransform PR #372](https://github.com/playcanvas/splat-transform/pull/372) / [`65ad6e2`](https://github.com/playcanvas/splat-transform/commit/65ad6e235549655ad7945e93c82c7846d207cc1b)。
- **新增**：Editor 在压缩设备丢失后销毁缓存 device、给出可重试错误，下一次导出重建设备；转换器同时销毁泄漏的 Compute 对象，并按 centroid range 拆分 SH palette k-means，避免长 command buffer 触发 macOS GPU watchdog。
- **实际影响**：对 627K splat 的 Apple GPU 导出故障是直接修复；#1094 让失败可恢复，#372 从根因降低 watchdog 风险。建议立即对 Mac 大场景 SOG export 做回归。
- **可运行性**：可实际测试；MIT；WebGPU；**可信度 B**。作者报告 M4 Max 大 palette 用例 2.19→2.09 s / 3.42→3.23 s，小用例 56→50 ms，主要收益是稳定性而非数量级加速。

:::

[原始发布](https://github.com/playcanvas/supersplat/pull/1094)

## X-Gaussian 公开真实 CT 数据与预训练模型

X-Gaussian 用高斯表示研究 X 射线和 CT 重建。此次加入真实扫描数据、预训练模型和配置，让研究者能从现成材料复跑真实数据路径，而不只评估合成图像。

作者的三维指标使用全视角 FDK 重建作为伪参考，不能当作真实 CT 几何真值。运行仍需相应 Linux、NVIDIA/CUDA 环境；当期未找到根目录许可证，公开可下载不等于商业使用条件已明确。

:::details[发布内容与使用条件]

- **时间 / 一手来源**：2026-11-09；commit [`5bc233d`](https://github.com/caiyuanhao1998/X-Gaussian/commit/5bc233d062e100d9ddd78dff9cd769768b418f59)，[仓库](https://github.com/caiyuanhao1998/X-Gaussian)。
- **新增**：FIPS Pine、Seashell、Walnut 的 50-view training / 100-view held-out 数据与 Hugging Face 权重；加入真实扫描 config、FDK 初始化缓存和 conservative voxel culling。
- **口径**：作者列出的 3D 指标以 full-view FDK 为伪参考，并非实测 CT ground truth；不能和有真值合成集直接横比。
- **可运行性**：代码 + 权重 + 数据可跑；Linux、CUDA 11.8、Python 3.9、PyTorch 2.1.2、GCC 11，约 30k + 1k steps；**根目录未检到 LICENSE，许可待确认**；**可信度 B**。

:::

[原始发布](https://github.com/caiyuanhao1998/X-Gaussian/commit/5bc233d062e100d9ddd78dff9cd769768b418f59)

## Spirula 加快漂浮点抑制并增加强抑制预设

Spirula Studio 调整训练中识别和抑制漂浮杂点的计算方式，并增加更强的抑制预设；掩码也可以在界面中重命名和删除。它影响的是扫描清理与训练反馈，适合用保留细线、远景的样本观察抑制强度是否合适。

作者报告的加速只对应一张显卡、一个场景中的正则化步骤，不能直接换算成完整训练提速。

:::details[发布内容与使用条件]

- **一手来源**：[`2d018a2`](https://github.com/harry7557558/spirula-studio/commit/2d018a2fe85b8c1c4d7750689033774a6de6e736)、[`4c099ab`](https://github.com/harry7557558/spirula-studio/commit/4c099abdf5d689c1ccf7708af330a8df424fde17)、[`337cbea`](https://github.com/harry7557558/spirula-studio/commit/337cbea311bbf3ca3c8271789c1847d4e88484bb)。

- **性能口径**：作者在 RTX 5070、1M splats、k=31 bicycle 上报告 regularizer pass：Vulkan 7.48→约 2.16 ms，CUDA 8.74→约 1.73 ms。仅是单卡单场景 microbenchmark。
- **可运行性**：可实际测试；GPL-3.0；Vulkan/CUDA；**可信度 B**。

:::

## visloc-rs 缩短训练中的光栅反向计算

visloc-rs 优化了高斯训练中计算图像误差梯度的 GPU 步骤，减少线程之间的协调。作者在一个建筑场景中报告该步骤约快 15%，完整训练时间则仅从 711 秒降到 698 秒。

这对维护原生训练流程的开发者有参考价值；同一测试里的画质差异属于运行波动，不能把速度修复写成重建质量提升。

:::details[发布内容与使用条件]

- **一手来源**：[PR #500](https://github.com/rsasaki0109/visloc-rs/pull/500)，merge commit [`8640046`](https://github.com/rsasaki0109/visloc-rs/commit/8640046f6df0a9138c1b1f7ad0d75dd6aa957443)。
- **新增**：每个 warp 独立 staging 32 splats，以 `__syncwarp` 代替 block-wide 协调，并从该 warp 最后 blended entry 反向遍历。
- **性能口径**：作者在 south-building 1.35M scene 报告 `raster_bwd` 约快 15%（每步约省 0.9 ms），30k steps 698 s vs 711 s；held-out 22.92 vs 23.02 dB 属运行波动范围，未宣称质量提升。
- **可运行性**：可实际测试；MIT OR Apache-2.0；Rust/CUDA；**可信度 B**。

:::

## Open-DiffusionGS 增加在线演示与网格导出

Open-DiffusionGS 为生成式静态三维内容提供在线物体、场景演示，并修正网格提取与坐标问题。结果可导出为带颜色的 OBJ 或自包含 GLB，方便带入常见三维工具与网页。

在线演示降低了试用门槛，但本地运行仍需匹配 CUDA 环境；当期许可证尚待确认。这里是旧研究的访问和交付能力更新，不是动态高斯重建，也不代表已独立验证每个导出文件。

:::details[发布内容与使用条件]

- **一手来源**：[仓库](https://github.com/caiyuanhao1998/Open-DiffusionGS)、[`beb6a03`](https://github.com/caiyuanhao1998/Open-DiffusionGS/commit/beb6a03e8fbab4342fbb8df00da734bd1ccafa3a)、[`4a2c75f`](https://github.com/caiyuanhao1998/Open-DiffusionGS/commit/4a2c75fca7fafdb554bc2378c144cab01c6ba956)。
- **新增**：物体/场景 Hugging Face Spaces；修复输入坐标、空 mask 和 mesh 坐标回世界空间；以 cKDTree 避免逐 tile 扫全云；输出带 Gaussian DC/opacity 插值颜色的 OBJ 和 Y-up、自包含、`KHR_materials_unlit` GLB。
- **可运行性**：代码 + 权重 +在线 demo；本地验证环境为 Linux / NVIDIA、CUDA 12.1、Python 3.11、PyTorch 2.5.1、GCC 12；**根目录未检到 LICENSE，许可待确认**；**可信度 B**。

:::
