## PERF-GS 用图形计算栈打开跨厂商训练路线

EA SEED 发布的 PERF-GS v1.0.0 以 Slang 编写训练核心，走 Vulkan 或 D3D12，在 NVIDIA 与 AMD GPU 上运行，不依赖 CUDA 或 PyTorch。独立应用把 COLMAP、检查、训练、查看和导出串在一起，也保留无界面入口。[发行页](https://github.com/electronicarts/perf-gs/releases/tag/v1.0.0)和[仓库](https://github.com/electronicarts/perf-gs)都已公开。

作者的 RTX 4090 数据把训练循环压到 10.51—122.66 秒区间，RTX 4050 6 GB 的 Balanced 记录约 2.80 GiB；但它们不含 COLMAP、载入和导出。Windows 的 NVIDIA/AMD 路径最清楚，Linux 与 macOS 未验证。真正值得做的是同数据、同预设的 RTX/RX 端到端对照，而不是直接转述“秒级训练”。

## SuperSplat Viewer 1.44.0 要求跨设备验收

SuperSplat Viewer v1.44.0 正式包含宿主控制信息面板、容器全屏、滚轮与快捷键的嵌入改造，并允许完全关闭 info 入口。XR 双手缩放扩大到 0.1—10 倍，VR 中新增地面网格；两项仍缺头显实测。[正式 release](https://github.com/playcanvas/supersplat-viewer/releases/tag/v1.44.0)已可用。

stochastic raster 把颜色解码移到 vertex 阶段后，维护者测得 A15 明显变快，Pixel 7 Pro 和 M4 Max 的部分模式却回退几个百分点，RTX 4090 基本持平。WebGPU 又缺少可靠的 adapter 分流信息，因此这不是“一律更快”的升级。依赖 Viewer 的产品必须覆盖手机、Apple Silicon、桌面独显与目标头显。

## HoloLab 把真实扫描交付为机器人仿真场景

HoloLab 的 Robot Simulation Starter Kit 用 XGRIDS 扫描现实空间，把 3DGS 作为视觉层、网格作为碰撞层，再导入 NVIDIA Isaac Sim。首批目标包括 Unitree G1、Go2 和 Boston Dynamics Spot，另有现场扫描、PC 配置、地形训练与真机验证服务。[官方新闻稿](https://prtimes.jp/main/html/rd/p/000000161.000023638.html)给出的价格口径是询价。

它说明高斯场景开始进入机器人仿真的服务交付，但官方没有公开场景规模、Isaac Sim 帧率、控制频率或 sim-to-real 成功率。采购判断应围绕尺度误差、碰撞简化、坐标一致性和目标机器人边界，而不是只看视觉逼真度。

## KIRI Engine 4.4.0 支持 360 视频直传 3DGS

KIRI Engine 4.4.0 的 [App Store 记录](https://apps.apple.com/us/app/kiri-engine-3d-scanner-lidar/id1577127142)确认：Web 端 3DGS Scan 接受 360 视频，Manual Capture 可以录制视频，单次输入提高到 500 张照片或 5 分钟视频。它减少了全景视频拆帧与整理步骤，也给长走拍明确了上限。

版本说明没有给出“画质提升”的数据集或指标，也没有明确新上限适用的订阅档位。已有 KIRI 订阅和 360 相机的团队，可以用同一素材比较视频直传与人工拆帧的上传、失败恢复、训练时间和结果，而不应把商店更新当成评测结论。

## LichtFeld 分开训练 ROI 与点云裁剪

LichtFeld Studio 的 [PR #4081](https://github.com/MrNeRF/LichtFeld-Studio/pull/4081)让训练 ROI 和点云 crop 拥有独立的形状、变换、可见性、撤销与序列化 role。ROI 会跨越训练、暂停和完成状态，点云裁剪则继续支持椭球；旧工程缺少 role 时仍按原行为读取。

这项主干变化解决的是状态语义混淆，还修复了完成时按 ROI 裁剪后 Edit Mode 空白的问题。它没有新正式 tag，旧 cropbox 工程、训练恢复、完成后裁剪、撤销和 MCP/Python 调用应锁定提交回归。

## Spirula 减少反向无效像素并加入 EPnP

Spirula 的 [PR #429](https://github.com/harry7557558/spirula-studio/pull/429)在 8×8 tile 内跳过零梯度并压缩活跃像素，CUDA 与 Vulkan 共用路径；PR 给出了精确性测试，没有统一性能数字。另一项 EPnP 更新进入 RANSAC PnP 的局部重拟合，覆盖平面、近似平面和广角/鱼眼 bearing。

两条改动分别落在训练反向成本和相机位姿稳定性上，不能用一项 benchmark 代替另一项验收。建议固定场景比较 GPU 时间与最终梯度，同时用平面标定板和鱼眼数据验证位姿；当前仍是主干代码，不是正式发行。

## NCore 20 重做远端与异步传感器数据读

NVIDIA [NCore 20.0.0](https://github.com/NVIDIA/ncore/releases/tag/v20.0.0)同时支持 zarr-python 2/3、可选 zarr format v3，并为组件 reader 和 sequence open 增加异步 API。远端 `.itar` 可并发读取精确字节范围，本地路径加入缓存、positional read 和少复制优化。

作者报告本地全帧读取快 1.7—5.5 倍，运动补偿也有新路径；这些都是作者条件。release notes 同时列出多项 breaking changes，涉及 loader、构造、有效性返回、参数与异常类型。NuRec 或多传感器重建用户应先照迁移指南回归，不要只因性能数字直接替换数据层。

## MicroPasts 为文化遗产 viewer 补上比例与来源语境

[MicroPasts/splat-viewer](https://github.com/MicroPasts/splat-viewer) 0.1.2 是面向 React 18 与 WebGL 2 的 MIT 组件，支持 PLY、SPZ、SPLAT、KSPLAT、SOG，以及可分页的 RAD。它把比例尺、paradata 和 splat telemetry 作为一等界面：只有明确 `mmPerUnit` 才显示真实尺度，并记录采集、重建、来源和衍生资产。

本地文件只在浏览器内读取，但会完整载入；分享链接只带视角与显示参数，不包含本地资产。项目刚创建、仓库规模很小，SparkJS/WASM 包也建议懒加载。它适合原型和机构展示试验，不能仅凭功能列表判断生产成熟度。

## SplatBridge 1.4.0 的 Web 发布尚未在商店页闭环

媒体报道和演示称 SplatBridge 1.4.0 已支持 Unity WebGL2 与 WebGPU，但本期核对 [Unity Asset Store](https://assetstore.unity.com/packages/tools/particles-effects/splatbridge-real-time-3d-gaussian-splatting-3dgs-for-unity-334403)时，官方页面仍显示 1.3.2，并写明 WebGL 不支持。

这可能是商店审核或页面传播延迟，也可能是演示构建尚未成为购买者可下载版本。当前只能报道来源冲突，不能写成“商店已正式交付”。已购用户应先核对账号内包版本、Unity 6000.x 条件、WebGL2/WebGPU 路径和许可证，再决定是否安排迁移。

## VersionGS 与 SprintGS 分别重写动态存储和快速训练成本

VersionGS 用逐帧 Gaussian 状态和组内共享版本字典表示动态场景：未变化项复用旧版本，变化项才追加。作者报告快速舞蹈场景的前景 PSNR 提升 2.7 dB，并在 N3DV 与 Technicolor 上比 TAD-GS 少 6.0 倍和 5.7 倍存储；播放只需普通 rasterizer。目前没有找到官方代码。[论文](https://arxiv.org/abs/2611.33374)。

SprintGS 则从 scheduled tile culling、透明收敛项剪枝、反向 warp 通信和 fused loss 四处减少冗余。作者报告比 FastGS 快 2.15 倍，高质量设置快 1.81 倍；同样没有可核验官方实现。[论文](https://arxiv.org/abs/2611.33796)

两篇论文分别回答“动态高斯如何避免快动作退化并压缩存储”和“Gaussian 已经很少后，训练时间还花在哪里”。现阶段它们都是论文无代码，作者指标不能替代复现。
