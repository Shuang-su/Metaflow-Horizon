## 速览

今天最重要的工程变化来自 [EA SEED 的 PERF-GS v1.0.0](https://github.com/electronicarts/perf-gs/releases/tag/v1.0.0)：它用 Slang 编写训练器，通过 Vulkan 或 D3D12 同时覆盖 NVIDIA 与 AMD，不依赖 CUDA 或 PyTorch，并把 COLMAP 到训练的流程装进独立桌面应用。它不是又一个 Python 研究仓库，而是一条可以实际安装、用消费级显卡测试的新训练路线。

## 重点正文

### EA SEED 用 Slang、Vulkan 与 D3D12 做出可下载的跨厂商 3DGS 训练器

[PERF-GS v1.0.0](https://github.com/electronicarts/perf-gs/releases/tag/v1.0.0)于北京时间 11 月 26 日 07:36 发布，本期在昨日截止时间后补收。项目采用 BSD-3-Clause，训练核心以 [Slang](https://shader-slang.org/) 编写，可走 Vulkan 或 D3D12，在 NVIDIA 与 AMD GPU 上运行；README 明确写着不依赖 CUDA 或 PyTorch。独立应用内置从图像调用 COLMAP、检查相机与稀疏点云、选择预设、训练、查看与导出的流程，也提供无界面运行路径。

作者公开的 Windows 11 测试覆盖 RTX 4080、4090 和 Radeon RX 7900 XT；Linux 与 macOS 仍标为未验证。作者在 RTX 4090、Mip-NeRF 360 九个场景上的训练循环数据为：Quality 预设平均 22.68 秒、27.90 dB，Ultrafast 为 10.51 秒、27.13 dB，Quality+ 为 122.66 秒、28.227 dB。另一个 RTX 4050 6 GB 的 Balanced 记录为每场平均 139.88 秒、训练末端约 2.80 GiB。这些数字不含 COLMAP、载入和导出，且是作者条件下的汇总，本期没有独立复现。

发行后主干又用 [`26a4ca2`](https://github.com/electronicarts/perf-gs/commit/26a4ca2)修正 SlangPy 版本不匹配，用 [`3384d13`](https://github.com/electronicarts/perf-gs/commit/3384d13)补入 RTX 4050 数据，说明安装与低显存边界仍在快速收敛。**判断：P1、可实际测试；BSD-3-Clause；Windows 路线最清楚，Linux/macOS 未验证。它最有价值的不是某个单一“秒数”，而是把训练从 CUDA/PyTorch 专用栈带到跨厂商图形计算栈。建议用同一 COLMAP 数据分别跑 NVIDIA 与 AMD，记录端到端时间、显存、导出兼容和画质，再决定是否进入生产候选。**

### SuperSplat Viewer v1.44.0 正式收拢嵌入、XR 与随机光栅更新

[v1.44.0](https://github.com/playcanvas/supersplat-viewer/releases/tag/v1.44.0)于北京时间 11 月 26 日 21:15 发布。它正式包含昨日已经报道的宿主嵌入契约：信息入口交给 `onInfo` 回调、全屏限定到宿主容器、快捷键与滚轮由 bootstrap flags 控制，并支持安全设置导出 HTML 的 `title`。新加入的 [PR #376](https://github.com/playcanvas/supersplat-viewer/pull/376)还允许把 `onInfo` 设为 `false`，完全移除信息入口，适合由产品自身承担帮助与品牌层。

XR 侧，[PR #377](https://github.com/playcanvas/supersplat-viewer/pull/377)把双手缩放范围从 0.25—4 倍扩大到 0.1—10 倍；[PR #378](https://github.com/playcanvas/supersplat-viewer/pull/378)加入可切换的 VR 地面网格，状态保存在 `xrGrid`。两项 PR 都明确写着尚未在头显完成验证，因此“进入 release”不等于 Quest 或 Vision Pro 工作流已经验收。

[PR #379](https://github.com/playcanvas/supersplat-viewer/pull/379)改变 stochastic raster：除 picker hash 外移除 flat varying，把颜色解码从 fragment 阶段移到 vertex 阶段。维护者测得 iPhone 13 Pro Max 的 per-pixel GPU 帧时间下降 8%—16%、raster 部分下降 17%—19%；Pixel 7 Pro 反而增加 3%—7%，M4 Max 的 mobile 模式约增加 7%，RTX 4090 约在 ±1% 内，Quest 3 结果混合。因为 WebGPU 当前不能稳定暴露足够的 adapter 信息，改动没有按 GPU 分支启用。

这次没有改变 SOG/SPZ/PLY 解码、LOD 协议或流式格式，主要影响 Viewer 发布 API、XR 操作和随机渲染着色器成本。**判断：P1 正式发行；MIT；可信度 A/B。依赖 Viewer 的编辑器导出、自托管页面和共享 viewer settings 都值得升级测试，但必须覆盖 A15、Android、Apple Silicon、桌面独显与目标头显；只在 RTX 4090 上“没回退”不能代表移动端。**

### HoloLab 把 3DGS 外观与碰撞网格组合成 Isaac Sim 机器人场景

[HoloLab 官方新闻稿](https://prtimes.jp/main/html/rd/p/000000161.000023638.html)于 11 月 26 日发布“Robot Simulation Starter Kit”。流程先用 XGRIDS 扫描现实空间，再把数据同时处理为 3DGS 视觉表示和可碰撞网格，最后导入 NVIDIA Isaac Sim。官方列出的首批目标包括 Unitree G1、Go2 与 Boston Dynamics Spot，其他机器人需单独商谈。

这里需要把两种表示的职责说清楚：3DGS 提供接近真实采集的外观，碰撞、路径和物理接触仍由网格承担。套件包含一天上手培训和最长一个月的每周支持，官方给出的典型推进节奏约三个月进入实机场景验证；可选服务包括现场扫描、PC 设置、楼梯等特定地形的运动训练和真机验证。价格为询价。

官方没有公开 Isaac Sim 帧率、场景 splat 数、碰撞网格规模、机器人控制频率或 sim-to-real 成功率，因此本期不能把它写成性能突破。**判断：P1 商业行业方案，researched、未 tested；闭源，价格询问；可信度 A。新闻价值在于 3DGS 已作为真实环境的视觉层进入可购买的机器人仿真交付，而不是取代物理几何。采购前应索取目标 GPU、场景规模、碰撞简化规则、坐标/尺度误差与机器人支持边界。**

### KIRI Engine 4.4.0 让 360 视频直接进入 Web 端 3DGS Scan

[Apple App Store 版本记录](https://apps.apple.com/us/app/kiri-engine-3d-scanner-lidar/id1577127142)确认 KIRI Engine 4.4.0 已上线。更新允许把 360 视频作为 Webapp 的 3DGS Scan 输入，Manual Capture 模式也可直接录制视频；单次 3DGS Scan 上限提高到 500 张照片或 5 分钟视频。应用仍是免费下载、含内购，商店在本期核对时列出的年费与月费档位不止一种，实际价格会随地区、促销和订阅入口变化，不宜用单一数字概括。

360 视频降低了全景相机用户拆帧、整理再上传的人工步骤，也让长走拍更容易进入云端训练；500 张/5 分钟的限制则给现场采集一个明确上界。版本说明只写“improved 3DGS quality”，没有公开数据集、相机、质量指标或训练时间，因此不能据此声称画质已经量化提升。商店也没有明确说明新上限分别适用于哪些免费或付费档位。

**判断：P1 正式商业应用更新，researched、未 tested；iOS/iPadOS 15 以上，Web 处理仍依赖服务端；可信度 A。已有 360 相机和 KIRI 订阅的团队可以用同一素材比较拆帧照片与原视频入口，重点记录上传大小、失败恢复、有效帧抽取、训练时间、splat 与网格结果，而不是只看宣传片。**

### LichtFeld 把训练范围与点云裁剪拆成两个独立工具

[LichtFeld Studio PR #4081](https://github.com/MrNeRF/LichtFeld-Studio/pull/4081)于北京时间 11 月 27 日 05:02 合并，对应提交 [`d0b3b79`](https://github.com/MrNeRF/LichtFeld-Studio/commit/d0b3b798febe8c69eaf6cad02271c3a0ed51d872)。旧流程用同一套 crop 状态同时表达“只在这一区域训练”和“把这部分点云裁掉”，容易在暂停、完成或重新编辑时混淆。新实现把训练 ROI 设为紫色、点云 crop 设为黄色，两者有独立形状、变换、可见性和撤销状态。

训练 ROI 支持方框与多边形，不提供 ellipsoid；点云 crop 继续支持方框、椭球和多边形。ROI 会贯穿训练、暂停与完成状态，并可在结束时选择“crop to ROI”。场景序列化新增可选 role，旧工程缺少 role 时仍按原 primary 行为解释；原生、Python 与 MCP 工具也改为 role-aware。维护者同时修复完成时按 ROI 裁剪后 Edit Mode 视口为空的问题，并保留旧 `builtin.cropbox` 工具 ID 兼容入口。

同日 [PR #4216](https://github.com/MrNeRF/LichtFeld-Studio/pull/4216)让指针事件只发送给最上层浮动面板，减少重叠窗口误操作，但评审只明确覆盖 Windows。**判断：P1 主干编辑/训练工作流，GPL-3.0-or-later；可信度 B。当前没有新 release；训练团队应拿含旧 cropbox、暂停恢复和完成后裁剪的工程做兼容回归，确认序列化、撤销、MCP 调用和视口不会互相污染。**

### Spirula 同时减少反向光栅无效工作并补强广角相机位姿

[Spirula PR #429](https://github.com/harry7557558/spirula-studio/pull/429)对应提交 [`9ecc36e`](https://github.com/harry7557558/spirula-studio/commit/9ecc36e6e55b0a3fae538a332d1dbe2e1e805983)。反向光栅化先跳过零梯度像素，再在每个 8×8 tile 内压缩活跃像素，CUDA 与 Vulkan 都使用同一路径，并保持与相机模型无关。PR 提供精确性测试，但没有公开统一场景、GPU 和训练时长 benchmark，因此目前只能确认减少了无效工作，不能量化成固定加速比例。

[PR #425](https://github.com/harry7557558/spirula-studio/pull/425)增加 EPnP 绝对位姿求解，并用于 RANSAC PnP 的局部优化重拟合；实现覆盖平面和近似平面点、广角/鱼眼 bearing，最低 4 点且没有新增依赖。[PR #426](https://github.com/harry7557558/spirula-studio/pull/426)还会在 densification 结束后跳过 loss map、世界空间梯度评分与相关分配，避免训练后段继续为不再使用的致密化指标付费。

**判断：P1 主干训练与 SfM 更新；GPL-3.0，CUDA/Vulkan；可信度 B。值得做两类测试：一是同一训练任务比较反向阶段的 GPU 时间与最终梯度/画质，二是用平面标定板、鱼眼和背向 bearing 的数据验证 EPnP 稳定性。没有新 tag，也没有足够数据支撑“训练加速多少”的结论。**

### VersionGS：用版本字典保存快速运动动态高斯

[VersionGS](https://arxiv.org/abs/2611.33374)观察到依赖平滑时间函数或受限更新的动态高斯在快速运动帧上会明显掉质，于是直接保存逐帧 Gaussian 状态：未变化的 Gaussian 继续引用组内共享字典中的旧版本，变化项才追加新版本。光流、图像差异和渲染误差用于选择需要更新的项，字典再经过剪枝、模拟量化微调和图像编码。

作者报告 DanceNet3D 快速舞蹈序列的前景 PSNR 比最佳基线高 2.7 dB，最高运动帧相对低运动帧下降不足 0.3 dB；在 N3DV 与 Technicolor 上，存储量分别比 TAD-GS 少 6.0 倍和 5.7 倍，同时维持更高 PSNR。播放端只需普通 3DGS rasterizer，不需要运动网络。当前没有找到可核验的官方代码或权重，所有数字都来自论文。**编辑摘要：** 它把动态场景从“连续运动模型”改写成“可复用状态版本”，对快动作与离线交付都值得跟踪，但现阶段仍是论文无代码。

<!-- arxiv:2611.33796 -->

### SprintGS：从 tile、反向通信与损失图三处减少快速训练冗余

[SprintGS](https://arxiv.org/abs/2611.33796)建立在 FastGS 上：训练前期用逐步收紧的粗 footprint 做 scheduled tile culling，移除已经收敛且接近透明的 Gaussian；反向阶段减少 warp lane 间交换的数据；fused loss 则在前向同时计算损失与图像梯度，避免保存完整 loss map。

作者报告在相近质量下比 FastGS 快 2.15 倍，高质量设置快 1.81 倍，并称方法也能用于动态、稀疏视角与表面重建。论文没有给出可核验的官方实现；GitHub 上同名搜索结果不是这篇论文的训练代码，因此本期不把它标成“代码已开源”。**编辑摘要：** SprintGS 与 Spirula 当天的主干改动指向相同工程事实：当 Gaussian 数已经压缩后，tile 覆盖、反向通信与固定分辨率损失会成为新的主要成本；论文结论仍需代码和独立复现。

3. **扫描到机器人仿真先验证尺度与碰撞。** 对 HoloLab/XGRIDS 路线索取并测试 3DGS 与网格坐标一致性、碰撞简化、楼梯/狭窄空间、Isaac Sim 帧率和真机误差，不要用视觉逼真代替物理可靠。
4. **KIRI 360 视频入口做可重复 A/B。** 同一 360 素材分别走视频直传与人工拆帧，比较有效视角、上传/恢复、训练耗时、浮点噪声、网格质量和订阅限制。
5. **主干工具先锁 SHA。** LichtFeld 用 `d0b3b79` 回归旧 cropbox 与训练恢复；Spirula 用 `9ecc36e` 检查梯度一致性和 GPU 时间。两者没有新正式 tag，不应让生产依赖自动漂移。

## 覆盖与限制

本轮逐项尝试来源注册表六类来源及全部登记 URL。Radiance Fields 首页和工具目录可读，提供 PERF-GS、KIRI、NCore、MicroPasts 与 SplatBridge 的发现线索；关键事实回到 GitHub release/PR、App Store、HoloLab 新闻稿和 Unity Asset Store 核验。PlayCanvas 博客可读但没有晚于既有归档的新文章；Blender News 返回 HTTP 403。

Hugging Face Papers 可读；arXiv export API 查询端点未能直接读取，本期改用 arXiv 原页和论文索引交叉核验。四个登记 X 账号分别返回 HTTP 403 或 DisabledError，没有取得可验证原帖，也没有把搜索摘要当作原帖。Reddit 页面可读，但当前结果没有满足本窗口日期与一手证据条件的新增；B 站只返回浏览器版本提示；少数派首页可读但未出现相关新稿。中文补充检索主要得到旧教程或转述，未列为今日新增。

本期没有购买 KIRI、SplatBridge 或 HoloLab 服务，没有运行 PERF-GS、手机采集、Isaac Sim、XR 头显或 GPU 训练，也没有独立复现任何作者性能和论文指标。“可测试”只表示公开代码、安装包或功能入口已经存在。图片发现未作为阻塞条件，本期未归档无法稳定核验授权和持久性的远程图片。
