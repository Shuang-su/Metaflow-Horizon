## 速览

今天最可能改变团队选型的是 [Unreal Engine 5.9 Preview](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-9-release-notes) 中浮出水面的 Epic 自带 **Gaussian Splat Asset** 实验插件。Epic 社区教程已经演示把 PLY 直接导入 UE、生成资产并放进关卡；这结束了“UE 高斯只能依赖第三方 Niagara/自定义插件”的绝对判断，但它仍是 Preview、Experimental、默认关闭，公开教程也没有给出生产平台矩阵、LOD/streaming、编辑、碰撞、打包和 SPZ 支持边界。

[CARLA 1.0](https://carla.org/2026/11/17/release-1.0/) 则把 NVIDIA NuRec 26.04 接进开放自动驾驶模拟器：记录的真实驾驶场景可以由 NRE 容器渲染相机与 neural lidar，CARLA 继续掌管时钟、物理、Traffic Manager 和 actor。它把神经重建从离线回放推进到可改车辆、重跑交通参与者的闭环仿真，但样例全集约 1.5 TB，官方最低显存要求高于 24 GB、推荐高于 48 GB，且依赖受控数据访问和 NVIDIA 容器栈。

行业侧还有一条需要马上处理的迁移消息。[Volinga](https://www.volinga.ai/insights/volinga-begins-a-new-chapter-with-arquimea-ai/) 将能力并入 Arquimea AI，并在 12 月 1 日后停止销售 Suite 与 Unreal Plugin 新许可；现有订阅支持到期但不可续订，也不会再有新发行。与此同时，PlayCanvas 正式发布 [SuperSplat 3.9.0](https://github.com/playcanvas/supersplat/releases/tag/v3.9.0) 与 Viewer 1.43.3，把过去几天的 GSAF 时间序列、混合导入复核、撤销顺序、选择可见性、非循环时间线和 XR 控制器修复从主干推进到可锁定版本。

## 重点正文

### Unreal Engine 5.9 Preview 首次内置 Gaussian Splat Asset 实验插件

Epic 员工在 11 月 16 日发布的[官方社区教程](https://dev.epicgames.com/community/learning/tutorials/LeGVo/salpicaduras-gaussianas-en-unreal-engine-5-9-preview)确认：UE 5.9 Preview 自带 Gaussian Splat Asset 插件。它默认关闭，需要在 Edit → Plugins 中启用并重启编辑器；教程用一份 PLY 导入出可拖入关卡的资产，并展示 `Invert UE Tone Curve` 与 `Point Scale Factor` 两个外观控制。Epic 论坛同日把 2025 年“暂无内置计划”的旧答复更新为“现已内置于 UE 5.9”。

这件事的重要性在发行边界，而不在功能数量。此前 UE 高斯项目普遍要选择第三方插件、Niagara 粒子方案或 Cesium 的 3D Tiles 路径；现在 Epic 自己提供资产类型，团队至少可以把导入、序列化、关卡引用和未来引擎兼容性纳入官方插件路线。它也可能改变第三方插件的价值重心：从“能不能显示”转向编辑、LOD、streaming、格式互操作、碰撞、Sequencer、影视输出和大型场景管理。

但当前只能确认 **UE 5.9 Preview + 实验插件 + PLY 导入**。公开教程没有证明 SPZ/SOG、球谐阶数、动态 4DGS、Nanite/Lumen、移动端、XR、打包发行、网络复制、LOD 或 streaming 的支持；不要把 [UEFN 43.00](https://dev.epicgames.com/documentation/en-us/fortnite/43-00-fortnite-ecosystem-updates-and-release-notes) 的 PLY/SPZ 与移动端说明自动外推到 UE 5.9 插件。**判断：P0 平台原生支持信号；Preview/Experimental、可实际测试但不宜直接生产；可信度 A。**

### CARLA 1.0 把 NuRec 神经重建接入可交互自动驾驶仿真

[CARLA 1.0 发布说明](https://carla.org/2026/11/17/release-1.0/)与[官方 NuRec 集成文档](https://carla-ue5.readthedocs.io/en/latest/nvidia_nurec/)给出的路径是：把神经场景和 actor 轨迹装进 `.usdz`，CARLA 通过固定版本的 `nvcr.io/nvidia/nre/nre-ga:26.04.01` 容器批量渲染当个 tick 所需的相机帧，并可生成 neural lidar。CARLA 负责仿真时钟、车辆动力学、Traffic Manager 与重放 actor，NRE 负责从新视角渲染记录场景；用户还能替换车辆渲染资产或插入偏移克隆。

这比“在模拟器里放一张神经背景”更实用：同一条真实道路记录可以换 ego 车辆、重跑其他交通参与者，并保留 CARLA 传感器和控制接口。对自动驾驶数据团队，它提供从真实日志、OpenUSD/NCore、神经重建到闭环测试的公开集成点；对通用 3DGS 团队，它也说明高斯表示正进入物理 AI 的传感器仿真层，而不只服务可视化。

门槛同样清楚。官方列出 Ubuntu 22.04+、CARLA 1.0、Python 3.10+、Docker、NVIDIA Container Toolkit 与 NVIDIA GPU；NVIDIA 下载页给出的最低显存为高于 24 GB、推荐高于 48 GB。完整样例集约 1.5 TB，数据还需要 Hugging Face gated access。CARLA 1.0 另外升级到 UE 5.8，并要求 RTX 50 系列使用 570+ 驱动；这些条件应进入部署清单。**判断：P0/P1 生产链路预览；可实际部署验证，但硬件、容器、数据许可和存储成本很高；可信度 A。**

### Volinga 停售 Suite 与 Unreal Plugin，新项目应在 12 月 1 日前完成去留判断

[Volinga 官方公告](https://www.volinga.ai/insights/volinga-begins-a-new-chapter-with-arquimea-ai/)称，公司将团队和神经渲染能力并入 Arquimea AI，转向任务关键型无人系统的实时 AI、仿真与 agent 工作。Volinga Plugin 与 Volinga Suite 的新许可只销售到 2026 年 12 月 1 日；已有订阅在有效期内继续支持，但不能续订，产品也不再发布新版本。

这不是普通的品牌更名。依赖 Volinga Unreal 插件或 Suite 的团队将失去版本演进和续费路径，未来 UE、驱动、操作系统或资产格式变化都可能变成兼容风险。仍在交付期的项目应在截止日前保存安装包、合同与许可凭证，导出可迁移的 PLY/SPZ 等资产，记录可工作的 UE/驱动组合，并验证替代 viewer、DCC 或引擎插件，而不是等订阅到期后再做资产盘点。

公告没有披露交易条款，也没有承诺 Arquimea AI 会继续提供同一产品形态；因此只能把“技术转向与产品收束”写成事实，不能宣传成 Suite 的升级路线。**判断：P0/P1 商业兼容性变化；现有用户需立即制定迁移或冻结计划；可信度 A。**

### SuperSplat 3.9.0 把时间序列、导入复核和选择可见性推入正式版本

[SuperSplat v3.9.0](https://github.com/playcanvas/supersplat/releases/tag/v3.9.0) 相对 v3.8.1 包含 6 个提交。GSAF 现在按时间线 sequence 载入，并能同时播放多段序列；混合多文件拖入会先解析、分组和复核，不再把不兼容文件悄悄吞进同一操作。`MultiOp.undo()` 改为逆序撤销，避免组合编辑破坏依赖状态；非循环时间线在最后一帧停止，从末帧再次播放才回到开头。

最值得编辑器开发者看的，是 PR #1110 对交互状态与渲染路径的重构。它新增 mode strip，把 centers/rings、markers、markers-only、X-Ray、selection tint/outline 收进共享工具栏词汇，也同步扩展 WebMCP 的 `set_view`。X-Ray 关闭时，编辑器新增 ID pass 和 visibility buffer：先为选中层写入经过深度测试的 Gaussian ID，再把可见性散射到 projected renderer，保证 centers、rings 与选择工具使用同一帧的可见集合；这比只改按钮位置更接近一次选择/拾取语义统一。

正式版本同时包含此前主干的 GSAF、多文件导入和撤销修复，因此升级价值高于单点补丁。代价是导入 UI、选择 pass、工具栏和时间线都发生变化，应该用静态 PLY/SPZ/SOG、GSAF 多序列、stochastic renderer、X-Ray 开关、框选/套索/画笔、撤销重做和 camera path 做一轮回归。没有 release 说明表明 SOG/SPZ 编码、LOD 或 streaming 本身改变，不应把 3.9.0 解读成格式升级。**判断：P1 正式发行；MIT，可立即测试；编辑器与 4D 时间线用户值得升级，生产项目先跑选择和导入回归；可信度 A/B。**

### SuperSplat Viewer 1.43.3 正式修复 SteamVR 控制器误判，并放宽批注数量

[Viewer v1.43.3](https://github.com/playcanvas/supersplat-viewer/releases/tag/v1.43.3) 相对 v1.43.2 有 3 个提交：把 annotation 上限从 20 提到 50；合入 PR #368，区分裸手与“同时暴露 hand skeleton 的控制器”；随后更新版本。控制器仍有按钮和摇杆时不再被手追踪路径接管，模型姿态、teleport、grab、掌心菜单与 AR placement 因此回到控制器逻辑。

这一修复此前只在主干、模拟 SteamVR 控制器和 Quest 3 上验证，现在至少有了可锁定 tag，但维护者没有宣称真实 Steam Frame 实机已经验收。WebXR 团队应比较 v1.43.2 与 v1.43.3，覆盖裸手、普通控制器、带骨架控制器、session restart、左右手切换和 50 个 annotation 的编辑/分享状态；普通桌面 viewer 用户不需要只为 XR 修复紧急升级。**判断：P1 正式发行；MIT，可实际测试；XR 项目建议升级并做设备矩阵，可信度 A/B。**

## 简讯

### LichtFeld 主干让 `convert` 导出完整可见工程场景

LichtFeld Studio 提交 [`e9aefe9`](https://github.com/MrNeRF/LichtFeld-Studio/commit/e9aefe9816c5603e7d634559e77950f5e2a94183) 不再把 `.licht` 限制为单个 checkpoint 或单个 splat，而是合并所有可见 splat 节点，应用父级可见性、场景变换、启用的 crop 和各发布资产的 SH 阶数，再复用现有 `convert` 输出 PLY、SOG、SPZ、GLB、USD、HTML 或 RAD。外部 RAD 会以完整细节载入，脚本可通过 `convert --capabilities` 检查 `visible-project-splats-v1`。

这是批处理和交付链路的重要补口：工程里多模型、变换和裁切终于能从 CLI 得到与可见场景一致的导出。但 Undo 历史和无关 checkpoint 被排除，输出为非 RAD 时会提取 LOD 叶节点，完整细节可能带来较高内存/时间；变更仍在主干，最新正式版仍是 v0.5.4.2。**判断：P1 主干可测试；GPL-3.0，等待 release 或锁提交验证；可信度 B。**

### Spirula 改善 SuperSplat 交付坐标、遮罩导入与 AMD Vulkan 训练一致性

Spirula 提交 [`6900275`](https://github.com/harry7557558/spirula-studio/commit/69002756ce30a0a73374f31a79210f0928d80c00) 为每个 checkpoint 保留原生 `splat.ply`，同时生成以 run 命名的交付 PLY；启用 `--export-y-up true` 时，交付文件会连同 Gaussian 方向、SH 和 spherical-beta lobe 一起旋转到 SuperSplat 约定，而训练相机、meshing 与原生 checkpoint 坐标不变。硬链接可避免未旋转交付重复占用空间，失败时回退复制。

提交 [`b8e15cb`](https://github.com/harry7557558/spirula-studio/commit/b8e15cb8d7f8a2f45ca9b4fea3fa331181433caa) 让 Correct Masks 识别 `image.jpg.png`、tagged 名称和 flat mask folder 等导入遮罩，并让多相机手绘区域保持 camera-specific。另一提交 [`571044d`](https://github.com/harry7557558/spirula-studio/commit/571044dae76706fc5073174604cb4a72e828bf96) 把 Vulkan 的 FLIP mask coverage 从 float16 改成 float32：作者在 AMD R9700 上把全保留 mask 相对无 mask 闭式结果的最大梯度偏差从 8.3% 降到约 `4.9e-6`，代价是每像素临时覆盖数据由 16 B 增至 28 B；旧 CUDA kernel 不变。三项都仍是主干。**判断：P1 主干工程改进；GPL-3.0，Vulkan/CUDA；可信度 B。**

### 3D Tiles 2.0 已进入 OGC 批准投票，高斯 splat 是六个能力域之一

[Cesium 11 月 16 日公告](https://cesium.com/blog/2026/11/16/cesium-at-iitsec-2026/)称 3D Tiles 2.0 已提交 OGC，批准投票正在进行，六个能力域包括更深的 glTF 集成、时变内容、voxel、vector、AEC 扩展与 3D Gaussian splat。[OGC 的公开征求意见记录](https://www.ogc.org/requests/ogc-seeks-public-comment-on-proposed-3d-tiles-2-0-community-standard-work-item/)也明确把 3DGS 列为工作项目范围。

这是标准进度，不是“已经批准”。现有 Cesium ion、CesiumJS 与 Cesium for Unreal 已有 3DGS + LOD 工作流，但标准层仍应以最终投票和发布文本为准；现在适合验证 `KHR_gaussian_splatting`、SPZ 压缩、tile 层级与坐标精度，不适合把草案字段冻结为长期私有协议。**判断：P1/P2 标准信号；可信度 A。**

### 11 月 24 日的 Volumetric Media Town Hall 将集中讨论 4DGS 采集、压缩与 WebXR

[Metaverse Standards Forum 活动页](https://metaverse-standards.org/event/volumetric-media-town-hall-2/)安排 Dymensium、Chronospace、Gracia AI 与 PlayCanvas/Snap 分享真实 4DGS、Packed Gaussian UV maps、4DGS streaming/WebXR 与开源采集。它是即将举行的在线活动，不是已经发布的标准或产品；活动页的分项时间还有内部顺序错误，因此本期只记录 11 月 24 日 7:00—9:00 PST 的总时段和主题，不引用每个演讲的分钟表。**判断：P2 社区/标准早期信号；可信度 A。**

## 相关深读与行动建议

1. **UE 团队先建最小兼容矩阵。** 用同一 PLY 在 UE 5.9 Preview 的编辑器、Standalone 和 packaged build 中检查颜色、SH、透明边缘、相机远近裁剪、灯光/后处理、序列化、显存、Windows/Linux 与目标 GPU；只有官方文档或实测证明后，再扩大到 SPZ、移动端、XR 和 streaming。
2. **CARLA/NuRec 先算数据与硬件账。** 从单场景安装器开始，记录容器拉取、gated dataset、GPU 显存、相机数量、neural lidar、每 tick 延迟和磁盘占用；不要用 1.5 TB 全集做第一次验证。
3. **Volinga 用户在 12 月 1 日前做冻结包。** 保存安装包、许可、项目样例、导出资产与可工作的 UE/驱动版本，选至少一个替代 viewer/编辑/引擎路径做回读；这比抢购最后一个许可更能降低长期风险。
4. **SuperSplat 3.9.0 重点测选择语义。** 对同一场景组合 X-Ray、markers、rings/centers、stochastic renderer 和各种选择工具，核对遮挡边界、撤销顺序与 GSAF 多序列时间线；Viewer 1.43.3 单独按 XR 设备类型测试。
5. **LichtFeld 与 Spirula 先用小工程做往返。** LichtFeld 检查多节点变换、crop、SH 与 RAD 完整细节；Spirula 同时保留原生与 Y-up PLY，验证 SuperSplat 方向、相机 meshing 和遮罩路径，避免把交付坐标误用作训练坐标。
