## 重点正文

### Splat Repair 0.1.0 把高斯表面修补做成可下载工具

[Splat Repair v0.1.0](https://github.com/NicolasDrum/splat-repair/releases/tag/v0.1.0) 于北京时间 11 月 17 日 05:46 发布，对应提交为 [`8487b80`](https://github.com/NicolasDrum/splat-repair/commit/8487b80)。它不是把删除区域简单变透明，而是沿洞口拟合几何、复制邻近 splat，并保留尺度、旋转与球谐外观。Fast Fill 面向平面与缓曲面；Deep Fill 会先渲染视图、用 LaMa 补图，再把结果抬回 splat；还提供 Brush、Lasso、Rectangle、Clone Stamp、Move 和 floater 清理。

项目为 Apache-2.0，Electron + PlayCanvas WebGPU 负责界面，Python 子进程负责格式、修补与文档状态，两端用进程管道通信而不开放本地 HTTP 端口。它读取和写出 PLY、`.splat`、SPZ，其中 PLY 是作者承诺可 bit-exact 往返的工作格式。普通安装要求 Windows 10/11、Node.js 22+、Python 3.10—3.13；Deep Fill 另需 NVIDIA GPU、CUDA、MSVC 构建工具，并会下载约 3 GB 依赖。

性能边界必须连同场景写清。作者在 55 万 splat 的扫描上报告 Fast Fill 约 0.3—1.5 秒，Deep Fill 在 RTX 4090 上约 20 秒；强重复浮雕和鞋底等复杂形状仍可能需要 Clone Stamp 手修。项目只有单作者八天开发的首个公开版，也只在 Windows + RTX 4090 测过。**判断：P1，可实际测试；优先用副本验证墙面、标牌和小遮挡物，不要直接改唯一母版。可信度 A/B。**

### Vauss 把视频到 SPZ、Blender 和碰撞网格收进一条 CLI

[Vauss](https://github.com/voyager-so/vauss) 在 11 月 12 日公开，11 月 15 日发布当前候选版 [`vauss-v0.1.25-rc`](https://github.com/voyager-so/vauss/releases/tag/vauss-v0.1.25-rc)，本期按 7 日重查补收。一个 `vauss run` 会检查视频、选帧、求解相机、训练 splat、跑留出视角评估并写出浏览器 viewer、SPZ web scene、Blender pack、体素游戏与可选碰撞/Unity 目录。固定流程不需要 AI 账号；Codex、Claude Code 和 MCP 客户端也能调用同一套 typed tools。原始 `.insv`/`.360` 还不能直接读，需先导出拼接视频；鱼眼和 2:1 equirectangular 输入有独立路径。

训练器以 Rust、Burn、CubeCL 和 wgpu 构建，经 Vulkan、Metal 或 DX12 运行，不强制依赖 CUDA。作者建议从 8 GB GPU、16 GB 内存起步，并提供 Linux x64、macOS arm64 与 Windows 包。源码可见，但原生 Vauss 代码使用 **Vauss Preview License**：研究预览期可免费商用和内部修改，却禁止未经许可分发修改版或提供托管服务，因此不能称为开源；Brush 派生训练 crates 仍是 Apache-2.0，其他组件各自保留许可。

作者在 7 个 Mip-NeRF 360 场景、每个 3 次、L40S、100 万 splat 上限和 30,000 steps 的对照中报告 Vauss 平均 127 秒、gsplat-MCMC 1.5.3 为 679 秒，即 5.4×，峰值显存为后者的 0.43—0.56 倍，7 个场景 LPIPS 均更低。另一组 RTX PRO 6000、9 场景 tuned recipe 报告 195—342 秒与平均 28.521 PSNR；两组配方不能混成一个“普遍 5.4×”结论，本期也未独立复现。**判断：P1，可实际测试；价值在端到端可重复管线和非 CUDA 后端，许可与 benchmark 口径是采用前的两项硬门槛。可信度 B。**

### Terra 把高斯查看器变成影视制作协作工作区

[District Cinema Terra](https://districtcinema.com/terra) 于 11 月 16 日对公众开放自助使用。它面向勘景、布景、机位与跨部门评审，而不只是“上传一个 PLY 看看”：浏览器内有批注、测量、书签、实时多人协作、虚拟摄影机、关键帧镜头、Rigging/CAD 导出、天气效果和共享链接。格式覆盖 PLY、SPZ、SPLAT、KSPLAT、SOG/SOG LOD、LCC/LCC2，以及 GLB/glTF、FBX、OBJ、STL、USD、Cesium 3D Tiles、HDR/EXR 与压缩包；渲染路径列出 WebGL 2/WebGPU、LOD 预设、3D Tiles streaming 和 Vision Pro/Quest XR。

截至本期核对，免费层给 15 GB 工作区存储、每月 5 GB 处理量和每场景不限 viewer；Starter 为 29 美元/月，50 GB 存储、15 GB 月处理量、无限项目及每场景 5 名 editor；Production 为每成员 79 美元/月、最多 15 人，Enterprise 可谈 on-prem。官网同时写有 REST API + OAuth 2.1，但具体 API 范围、数据驻留、优化产物可下载权限和团队权限仍要按实际计划确认。

这是一项商业云服务，本期只做资料核对，没有上传资产或测试协作延迟。**判断：P1 商业产品；对影视/VFX 团队的新闻价值在“高斯进入可计费、可权限管理的制作协作层”，不是渲染器本身。先用非敏感样片验证格式回读、LOD 质量、下载权限与 XR 设备，再决定是否迁移正式项目。可信度 A。**

### SPZ 动态扩展给出可互操作草案，但离流式生产格式仍远

Niantic 的草案 [PR #117](https://github.com/nianticlabs/spz/pull/117) 在 SPZ v4 上定义 `SPZ_NIANTIC_temporal`（扩展 ID `0x4E530003`）。核心 SPZ 仍保存 poster frame，因此旧 reader 忽略扩展后至少能显示正确静态帧；扩展帧则携带逐点位置/旋转多项式、不透明度时间窗，以及可选的最多 8 个刚性 driver 蒙皮、driver 关键帧和名称。实现同时加入 C++、Python、WASM binding、`spz_to_ply --time` 和 PlayCanvas viewer。

扩展数据放在核心流之后的 zstd skippable frame 中，默认加载选项会跳过 temporal 数据。这一兼容策略很有价值：静态工具不会完全失效，动态工具又能读出时间属性。但当前 head [`c6e9110`](https://github.com/nianticlabs/spz/commit/c6e9110a9bef859a38226b6de092cc27724ac57d) 仍是 WIP，PR 明确承认只有通用 zstd、统一精度、没有 frame reuse、分段、streaming 或 GPU evaluation，全部在 CPU/WASM 解码与求值；示例 164 帧 × 10 万点会生成 243 MB 文件，转换峰值约 10 GB，而且尚未新增测试。

**判断：P1/P2 互操作原型；适合格式、播放器和 4D 工具作者提前做隔离分支，不适合作为交付标准或承诺 Web 端大场景性能。可信度 B。**

### PlayCanvas 主干修正撤销顺序与 XR 输入设备识别

[SuperSplat PR #1109](https://github.com/playcanvas/supersplat/pull/1109) 合入提交 [`f29e2b4`](https://github.com/playcanvas/supersplat/commit/f29e2b4a34ecee6e4e4886630d653324c5b07add)，把 `MultiOp.undo()` 从原顺序改为严格逆序。组合操作若按 A→B 执行，撤销必须 B→A；当前调用者没有被确认的可见故障，但依赖同一 splat 范围或状态的后续操作会因此避免历史栈破坏。正式 release 仍是 v3.8.1，所以这是应补回归用例的主干正确性修复，不是用户已收到的新版本。

[SuperSplat Viewer PR #368](https://github.com/playcanvas/supersplat-viewer/pull/368) 与 [PlayCanvas Engine PR #10053](https://github.com/playcanvas/engine/pull/10053) 则区分“裸手”与“同时暴露 hand skeleton 的控制器”。这针对 Steam Frame / SteamVR 一类输入：旧逻辑可能把控制器误当手，导致模型出现在原点、传送只在某些腕部角度触发、抓取需要 trigger+grip 同按，菜单也只接受掌心手势。Viewer 先带临时补丁，Engine 提交 [`a0de85c`](https://github.com/playcanvas/engine/commit/a0de85c7f2ffe350877cbb94c1b6391860db76c4) 再把判断下沉核心。

维护者用模拟 SteamVR controller 和 Quest 3 做过验证，但没有在真实 Steam Frame 上实测；Viewer 最新 release 仍是 v1.43.2，Engine 最新正式版仍是 v2.24.1。**判断：P1 主干修复；普通桌面 viewer 无需追主干，正在做 WebXR/SteamVR 的团队可以锁提交做输入矩阵测试。可信度 B。**

### Splat Prep 1.0.1 为 Blender 5.3 补齐高斯导出和变换修正

[Splat Prep 1.0.1](https://nico-hartl.itch.io/splat-prep-import-fix-clean-up-and-export-gaussian-splats) 是售价 19 美元的 Blender 扩展，11 月 15 日发布、本期补收。它针对 Blender 5.3 已能导入/渲染 splat、但普通 Apply Transform/Join 只移动中心而不更新方向、尺度与球谐的问题，提供高斯专用变换与合并；还能读取 compressed PLY 和 `.splat`，写出标准 PLY、compressed PLY、SPZ 与 `.splat`，并提供找 floater、裁切、调色、降采样预览、proxy mesh 和 mesh-to-splats。

扩展要求 Blender 5.3+，作者只在 Windows 5.3.0 测试；SPZ、compressed PLY 和 `.splat` 都是有损路径，`.splat` 不含视角相关颜色，细刺等薄结构可能在 Reduce 中先丢失。商店只在购买包中附“licence”，公开页没有给出可核查的源码许可，因此应按闭源付费扩展理解。**判断：P1 商业插件；适合已有 Blender 5.3 高斯资产的人先验证 transform、SH 旋转和往返格式，不是 Blender 官方导出器。可信度 A。**

### Stage-wise Lineage-aware Dropout 把 densification 后代关系用于稀疏视图正则化

[Stage-wise Lineage-aware Dropout for Sparse-View 3D Gaussian Splatting](https://arxiv.org/abs/2611.17752)（arXiv:2611.17752）把初始化 Gaussian 视为 founder，把 clone/split 出来的后代归为 lineage family。结构正则阶段按“家族”一起 dropout，后期再切回单个 Gaussian dropout；Lineage-Balanced Densification 则用家族平均梯度和后代数重新分配固定 clone/split 预算，避免少数家族持续膨胀。

论文在 LLFF 3-view 报告 20.70 dB，较 DropGaussian 的 20.33 dB 高 0.37 dB；但其 SSIM 0.717 低于 DropAnSH-GS 的 0.724，LPIPS 0.194 与后者相同。作者还在 Mip-NeRF 360、Blender 以及 FSGS、CoR-GS、DNGaussian、Scaffold-GS 接入中报告改善。实验基于 DropGaussian 协议，复现实验平均 3 次；本轮没有找到作者代码或权重。**判断：P2，论文无代码；思想可迁移，数字不能替代独立复现。可信度 A（论文事实）/B（作者实验）。**

<!-- arxiv:2611.17957 -->
### MacroGS 让一个宏像素的 Gaussian 在多视角光场之间共享

[MacroGS: Macro-Pixel Shared Gaussian Primitives for Arbitrary-Scale Light Field Super-Resolution](https://arxiv.org/abs/2611.17957)（arXiv:2611.17957）不再为每个输出视角分别预测一套 Gaussian，而是让同一 macro pixel 的多视角观测共同预测一组 primitives，再用视差控制位置替换、用视角条件控制外观。这样每个请求尺度下的 primitive 数不随输出视角数线性增长，目标是把任意倍率光场超分的空间与角度冗余一起消掉。

作者在 5 个 benchmark 上报告固定倍率质量提升，并称解码速度相对隐式光场 decoder 为约 2—10×、相对逐视角 Gaussian baseline 为 10—18×；这些倍数取决于分辨率、视角网格、encoder、GPU 和质量约束，摘要没有足够条件支持泛化。本轮没有找到可核查的代码或权重链接。**判断：P2，论文无代码；它更接近 2D/光场 Gaussian decoder，而不是可直接替换场景 3DGS 训练器。可信度 A/B。**

## 相关深读与行动建议

1. **先测试 Splat Repair，而不是先看深度补图。** 用同一份 PLY 副本分别做小平面洞、缓曲面、重复纹理和薄结构，记录 Fast Fill 时间、splat 数变化、远近视角破绽、撤销与 PLY bit-exact 往返；只有几何路径不够时再安装 3 GB Deep Fill 依赖。
2. **Vauss 与现有 trainer 做配对基准。** 固定帧、相机和 100 万 splat 上限，记录求解、训练、评估和导出各阶段墙钟时间、峰值显存、PSNR/SSIM/LPIPS、最终 splat 数和格式体积；同时让法务确认 Preview License 是否覆盖内部修改、客户交付和自动化服务边界。
3. **SPZ temporal 只做实验分支。** 用 poster frame 退化读取、`--time` 抽帧、driver 蒙皮和 WASM 内存作为第一轮互操作检查；不要在没有分块、随机访问和 GPU 求值前把它接入大规模 streaming 承诺。
4. **XR 团队做设备类型矩阵。** Quest 3 裸手/控制器、SteamVR 模拟输入和真实目标设备分别核对模型姿态、teleport、grab、menu 与 session restart；不要把模拟通过写成 Steam Frame 实机通过。
5. **Terra 与 Splat Prep 先用非敏感资产。** Terra 检查权限、原件/优化件下载和 API 范围；Splat Prep 检查 SH 旋转、非均匀缩放、compressed PLY/SPZ 往返和 Blender 后续官方 exporter 的重叠边界。
