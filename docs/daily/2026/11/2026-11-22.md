## 速览

今天最值得立即拿来用的是迟到索引补收的 [QuickSplat v0.4.0](https://github.com/gabriverga/QuickSplat/releases/tag/v0.4.0)：Windows Explorer 和 macOS Finder 现在可以用空格键离线预览 PLY、compressed PLY、SPLAT、KSPLAT、SPZ、SOG 与常见点云文件。它没有把高斯编辑塞进文件管理器，而是把“先开大型编辑器才能确认资产”的摩擦降到一次系统预览。

动态内容与 XR 同时向可交付工具靠近。[ITHACA 4DGS for Unity](https://github.com/frenchtouchXR/ithaca-4dgs-unity) 接入 `.trgz` 高精度序列并修正片段时间原点；[PinchDrop](https://github.com/xibihe/PinchDrop) 则公开完整 Vision Pro 工程，让手机上的参考照片成为 ARKit 跟踪锚点，再以手势展开配对的高斯场景。两者都有源码，但前者是 Unity 主干能力，后者受 visionOS 26、开发者签名和非商业许可限制。

今天凌晨的主干更新更偏工程可靠性。Spirula 为随机式高斯预览、低内存串行回退和失败诊断连续落地提交；LichtFeld Studio 修正非标准图片目录的数据集先验图生成，并给外置面板加固定状态；SuperSplat Viewer 统一主题色与字体。它们都不是新 release，不应直接写成“所有用户已经获得”。

### QuickSplat v0.4.0 把高斯资产预览接到系统空格键

[QuickSplat v0.4.0](https://github.com/gabriverga/QuickSplat/releases/tag/v0.4.0) 的 release 对应提交为 [`a5d4d8e`](https://github.com/gabriverga/QuickSplat/commit/a5d4d8e6e48437908c73a2fa370346a036f06cc1)，GitHub 显示发行于 11 月 20 日北京时间 06:06，本期因 11 月 21 日媒体索引补收。Windows 端是 QuickLook 插件，以 C# 和 WebView2 托管预览；macOS 端是 Swift 应用加 Quick Look extension，要求 macOS 13 及以上。两端共享基于 Three.js 与 World Labs Spark 的离线查看器。

当前支持 Gaussian PLY、compressed PLY、SPLAT、KSPLAT、SPZ、SOG，以及 PLY/PCD/XYZ/XYZRGB 点云；支持轨道相机、重置视图、坐标轴切换和基础文件信息。项目没有在后台上传资产，适合把它放在素材筛选、批量交付检查和格式迁移前端。限制也很明确：它是预览器，不提供编辑、格式修复或训练；Windows 依赖 QuickLook 与 WebView2，macOS 安装包采用临时签名和终端安装流程。

代码采用 GPL-3.0。对团队而言，最有价值的测试不是看一个示例是否能打开，而是拿自己的超大 PLY、SOG v2/v3、SPZ 与异常元数据文件测首帧时间、内存峰值、坐标朝向和崩溃隔离。**判断：可实际测试的桌面工作流工具；迟到补收；可信度 A。**

### ITHACA 让 Unity 直接播放 `.trgz` 高精度 4DGS

[ITHACA 4DGS for Unity](https://github.com/frenchtouchXR/ithaca-4dgs-unity) 在提交 [`8fdac59`](https://github.com/frenchtouchXR/ithaca-4dgs-unity/commit/8fdac5957f94af1f4ea3fd4688ede1f2804b7a92) 中加入 `.trgz` 序列：解码 Trigs，每个 splat 以旋转与平移构成的 screw motion（螺旋运动）随时间变化，并用二次 Bézier 曲线控制速率。`.trgz` 可以单独播放，也可以装入此前的 `.4dgs` 单文件容器；资产创建器随后在 [`fe4ee7c`](https://github.com/frenchtouchXR/ithaca-4dgs-unity/commit/fe4ee7c74266746062013bc9e99883e23c2536f6) 接受这种输入。

北京时间今天 07:41 的 [`7068ac6`](https://github.com/frenchtouchXR/ithaca-4dgs-unity/commit/7068ac6e489ea1d0e3d5f18f80a9d464d0a50fbd) 又把 `.trgz` 的时间原点对齐到第一张训练帧，使其进入已有片段转场时不再按错误时间起算。这个细节比“支持一种新扩展名”更重要：4D 片段一旦要跨序列淡入淡出，训练帧窗口、局部时间和容器时间必须指向同一基准。

仓库是 MIT，基于 Unity 6000.0.77f1 与 URP，可通过 UPM Git URL 安装；Windows 编辑器路径要求 DX12 或 Vulkan，DX11 缺少所需 wave intrinsics。仓库没有对应 release tag，训练器、示例资产与平台服务也各有独立许可。建议先用短 `.trgz` 片段验证时间原点、循环边界、交叉淡化、显存峰值与移动 XR 降级，再接入生产时间线。**判断：P1 主干可测试的 4DGS 播放链路；可信度 B。**

### Spirula 主干把随机式预览与低内存退化路径补进同一轮更新

Spirula Studio 在 [`e8b5b5f`](https://github.com/harry7557558/spirula-studio/commit/e8b5b5fe3ef5296fb772f73f4b0e459a8fae5bf8) 中加入 stochastic splats（随机式高斯绘制）并扩大硬件渲染器缓冲区。提交信息没有给出可复核的 GPU、分辨率、splat 数或质量对照，因此本期不把“加速”转写成倍数结论；它更适合视为新的预览路径，需要用同一相机和数据集检查噪声收敛、拖动响应与显存占用。

同一小时内的 [`3ca045c`](https://github.com/harry7557558/spirula-studio/commit/3ca045c89d7c6ebd69aaf911cd3e19e0eeafa029) 会在默认 worker 内存不足时先检查模型驻留量并退回串行执行，保留显式内存错误；[`9a80742`](https://github.com/harry7557558/spirula-studio/commit/9a807429dafc5a165c06bd2a0ffe1c99efef766b) 则让稠密重建的中间文件失败报告具体路径和 errno，避免“磁盘已满”只表现为模糊写入错误。查看器导入被拒绝后，提交 [`aea7631`](https://github.com/harry7557558/spirula-studio/commit/aea763135c56c2cf542bce1d1f127308d28ee577) 还会恢复浏览与模型状态。

这些改动共同改善大数据集和低内存机器上的可诊断性，但串行回退意味着任务可能显著变慢，随机式预览也不等于最终渲染质量提升。正式 release 仍未包含这些提交。**判断：P1 主干工程更新；GPL-3.0；应锁 SHA 做压力测试；可信度 B。**

### PinchDrop 把手机照片变成 Vision Pro 中的高斯场景入口

[PinchDrop](https://github.com/xibihe/PinchDrop) 提供完整 Xcode 工程、4 个配对作品和 Apple silicon Mac 预览。它不是把手机照片即时重建成三维：每个场景先把一张参考照片与一个准备好的高斯模型配对，Vision Pro 用 ARKit 识别手机上的图像和物理尺寸，再跟踪手势，在本地用 MetalSplatter 把粒子聚到掌心并展开场景；手势期间不需要云端识别或传输模型。

项目要求 visionOS 26、Xcode 签名与启用 Developer Mode，接受 SOG v2、SPLAT、SPZ 和兼容 PLY。作者给出脚本将照片与模型登记到场景清单，默认示例建议约 500,000 点，也可明确提高预算。北京时间 11 月 21 日 14:11 的 [`fa87d7d`](https://github.com/xibihe/PinchDrop/commit/fa87d7d5c636a48ecbf698dbabeb46c8a93025a4) 处理 compositor 取消帧，保证已取得的 drawable 被正确呈现。

代码与文档采用 PolyForm Noncommercial 1.0.0，随附照片与模型也限非商业使用；Apple ML-SHARP 预训练权重另限非商业科学研究，且项目不分发这些权重。它因此更像可复现的空间交互作品和原型，而不是可直接商用的 SDK。**判断：P1 XR 原型，源码与素材可运行但许可边界严格；可信度 B。**

### LichtFeld Studio 修正数据集路径，并让外置面板可固定

LichtFeld Studio 的 [`9790b11`](https://github.com/MrNeRF/LichtFeld-Studio/commit/9790b11906d5c4dee78bd2c6364e85effe779b2f) 修正了图片不在 `images/` 目录时先验图自动生成失败的问题：预处理与加载器共享 sidecar 相对路径规则，并在 basename 回退前先查相对键。对来自视频抽帧、外部数据管理器或自定义目录的项目，这是减少“文件存在但映射不到相机”的实际兼容性修复。

[`53e307c`](https://github.com/MrNeRF/LichtFeld-Studio/commit/53e307ce451a26b7ccc668242e71114e408ed834) 为支持的桌面面板加入会话级固定控制，并扩展内置浮动面板；Wayland 原生窗口会隐藏该功能。随后提交只是测试与样式债务整理。两项都在主干，尚无新发行版。**判断：P1/P2 主干可测试；GPL-3.0；可信度 B。**

### SplatBridge 1.3.2 把 Unity 内编辑与 HTTP streaming 写进正式商品能力

[Unity Asset Store 正式页面](https://assetstore.unity.com/packages/tools/utilities/splatbridge-3d-gaussian-splatting-import-stream-play-real-world--392164) 当前标记 SplatBridge 1.3.2、11 月 18 日发行、29.1 MB，支持 Unity 6000.3.28f1 的 Built-in、URP 与 HDRP，许可为 Standard Unity Asset Store EULA。商店页面和[更新说明](https://radiancefields.com/splatbridge-now-edits-gaussian-splats-inside-unity)列出的工作流包括五种体积选择、套索与笔刷、拆分／删除／提取、过滤与颜色／透明度修改、合并与重建 LOD，以及 SOG、streamed SOG ZIP 与 PLY 导出；运行时可从 HTTP 服务器分块读取资产。

这是闭源商业扩展，WebGL 不在支持范围，Quest 3 标为实验性，价格还会随商店地区和税费变化。本期没有设备实测，也没有把商品页能力推定为所有平台性能相同。**判断：P1 正式商业工具；可购买测试；可信度 A。**

### Shrunk 用手机扫描把高斯变成浏览器捉迷藏地图

[Shrunk](https://playshrunk.pages.dev/) 是已经可玩的浏览器捉迷藏游戏：7 个样板房间免费，Home Pass 以一次性 4.99 美元口径接收用户自己的 SPZ 或 PLY 扫描。房间最多 8 人，要求 Google 登录和 18 岁以上；作者称原始扫描留在本机，处理后的房间会进入服务存储并分发给同房玩家。

它没有公开源码或许可，也没有给出长期存储、删除和商业使用的完整技术边界。本期将它视为“高斯资产如何成为多人游戏关卡”的产品信号，而不是开源引擎。**判断：P2 已上线商业应用；可直接体验；可信度 B。**

3. **Spirula 的串行回退必须带超时和遥测。** 低内存机器不再立刻失败可能是好事，也可能让批处理悄悄跑数倍时间；记录回退触发、预计内存、墙钟时间和中间文件磁盘占用。
4. **PinchDrop 先做许可隔离。** 交互代码、随附作品、生成工具和 Apple 权重不是同一许可。商业原型应替换为自有资产与合规生成链路，再讨论部署。
