## 重点正文

### Viz Engine 5.6 把 Gaussian Splatting 接进广播图形制作链

[Vizrt 官方 5.6.0 发布说明](https://documentation.vizrt.com/viz-engine-rn/5.6/Viz_Engine_Release_Notes.html) 标注版本发布日期为 11 月 19 日，并把 Gaussian Splatting 列入关键新特性。本期于 11 月 25 日通过迟到索引补收，不把它误写成今日发布。[Radiance Fields 的工作流说明](https://radiancefields.com/vizrt-brings-gaussian-splats-to-viz-engine-5-6) 显示，Viz Artist 可在后台导入 SOG 与 PLY，创建多级细节（LOD），再以场景树中的 Geometry 对象使用；运行时采用八叉树 LOD、由后向前排序与四边形 splat，并支持最高 3 阶球谐颜色。

这使高斯第一次以“广播引擎内的普通场景对象”进入 Vizrt 的设计与播出链，而不是外部网页或视频素材。虚拟灯光提供叠加、相乘、相加等覆盖方式，适合演播室画面匹配，但不是对捕获场景做物理一致的重新照明。官方发布说明只确认特性与版本，具体导入和限制主要来自专业媒体对官方工作流的整理；本期没有获得许可证价格，也没有运行 Viz Artist。

当前限制包括：常规 shader effect、实例化与部分 tonemapper mask 不适用；镜面、玻璃、移动物体、随时间变化的光照与物理碰撞不会因为导入 splat 自动获得正确行为。**判断：P0/P1 商业生产工具正式发行；闭源、需 Vizrt 许可；可信度 A（版本与特性）/C（工作流细节）。已使用 Vizrt 的团队值得安排导入与播出稳定性验证，其他团队不应仅凭“原生支持”推断完整材质或物理能力。**

### OpenSplat4D 0.3 把 Unreal 的 3D/4DGS 渲染和编辑插件完整开源

[OpenSplat4D v0.3.0](https://github.com/YuanBaoSMadLab/OpenSplat4D/releases/tag/v0.3.0) 于 11 月 24 日发布，对应提交 [`683db2f`](https://github.com/YuanBaoSMadLab/OpenSplat4D/commit/683db2f)。项目把此前的 Unreal 插件源代码以 Apache-2.0 公开，并提供 UE 5.7、5.8、5.9 的 Win64 包。静态资产支持 PLY 与 SPZ；动态资产支持 STG PLY、逐帧 PLY 序列以及复旦 4D Gaussian 的单 PLY / `.pth` 路径。Postshot `.psht` 与 Volinga `.nvol` 不在支持列表。

渲染链由 GPU cluster culling、LOD compaction、radix depth sort 与 indirect draw 组成，另有 4D 播放器、逐 splat 阴影、碰撞和 Chaos fracture。运行边界是 Windows、DX12 与 Shader Model 6；Niagara、Geometry Collection、Planar Cut 与 Fracture 等插件按功能启用。发布包可直接测试，作者也提供训练脚本，但编辑器训练会获取 graphdeco-inria 的 `diff-gaussian-rasterization` 和 `simple-knn`，不能把插件的 Apache-2.0 自动延伸为整套训练依赖都可商业使用。

项目同时覆盖“看、播、交互、破碎”而非只做 viewer，对 UE 虚拟制作和 4D 人物原型有直接价值；不过作者说明对 Fudan 4D 流程的真实训练器兼容仍需按数据验证。**判断：P1 可实际测试；Apache-2.0 插件，训练依赖需单独审计；需要 UE 5.7+、Win64、DX12/SM6；可信度 A/B。建议马上用一份静态 SPZ、一份逐帧 PLY 和一份 Fudan 资产分别做导入、内存、排序、阴影与打包测试。**

### Orbit v26.11.23 开放多机位视频到 4DGS 的测试版训练

[Xangle Orbit v26.11.23 更新日志](https://xangleapps.com/orbit/changelog/v26.11.23) 明确新增 beta 4D Gaussian Splatting：输入同步多机位视频，训练后可把动画序列导出到 Splat Player，也能制作相机路径并导出 MP4。训练器是独立 Windows 程序，要求 NVIDIA CUDA GPU；这一版还增加低分辨率代理和备份修复，针对长素材先减轻交互负担，再降低工程损坏后的恢复成本。

官方没有在该日志中给出支持的相机数量、显存下限、训练时长、输出容器和价格口径，因此现在可以确认“功能入口可用”，不能确认它已经适合任意规模的制作。**判断：P1 商业工具 beta；Windows + NVIDIA CUDA；可信度 A。已有同步多机位素材的团队可用短片段验证时间同步、动态边缘、播放器导出和工程恢复，不宜直接迁移长周期项目。**

### PlayCanvas 增加逐相机 reverse-Z，但高斯与 XR 仍明确不在覆盖范围

[PlayCanvas Engine PR #10013](https://github.com/playcanvas/engine/pull/10013) 于北京时间 11 月 24 日 22:50 合并，对应提交 [`429141c`](https://github.com/playcanvas/engine/commit/429141c8d2f58c315c7e0bfc8e4cc3bfe5d593d0)。它为 WebGPU 相机增加 `reverseZ`，允许把深度缓冲的精度更多留给远处几何，且可按相机选择；这是主干能力，还不是新的正式 npm 版本。

对高斯用户更重要的是边界：实现没有应用到 XR view，读取 scene depth 的特效、picker、compute scene depth 和 Gaussian splats 都未覆盖。调试构建会在高斯路径发出警告，因为 splat 投影仍按普通深度，而深度测试可能已经反转。换言之，这不是“PlayCanvas 高斯也支持 reverse-Z”，而是一个需要主动避开的组合。

**判断：P1 主干渲染架构更新；MIT；WebGPU 可锁提交测试；可信度 B。普通 mesh 的大尺度场景可做深度精度 A/B 测试；包含 splat 或 XR 的相机应保持 `reverseZ=false`，直到上游明确补齐投影、深度读取与测试。**

### WildAnySplat 给无标定野外多视图重建提供可运行权重

<!-- arxiv:2611.31023 -->

[WildAnySplat 论文](https://arxiv.org/abs/2611.31023)面向互联网照片、截图与生成图等相机未知、外观不一致、视角稀疏的输入，把 VGGT-Omega 几何先验与外观建模结合，输出可渲染的 3D Gaussian。作者已经公开[推理代码](https://github.com/wildanysplat/WildAnySplat)和[预训练权重](https://huggingface.co/wildanysplat/WildAnySplat)，不要求用户先跑 COLMAP 或提供相机位姿。

公开安装要求 Linux、Python 3.10+、NVIDIA CUDA、与 PyTorch 精确匹配的 `torch-scatter`，并固定 `gsplat==1.4.0`；默认把输入中心裁剪到 448×448，示例默认最多 12 个视图，输出 SuperSplat 可读 PLY、相机和渲染视频。当前权重关闭了论文中的 bilateral-grid head，VGGT-Omega 也带有非商业研究限制，仓库顶层许可仍需项目方进一步明确。

**编辑摘要：** 这不是只有论文的“任意照片重建”宣称，而是代码与权重已经可下载的推理管线；真正需要验证的是裁剪、视图上限和上游非商业许可是否适合自己的素材与交付，而不是只看作者样例。

**判断：P1 研究原型，代码+权重可跑；许可边界待审；可信度 A/B。适合先用包含曝光变化、屏幕截图和弱重叠的 6—12 张小样，与 COLMAP+3DGS 基线比较位姿稳定性和漂浮物。**

### ArgsWorld 用一套自回归扩散模型统一重建、生成与世界外推

<!-- arxiv:2611.28792 -->

[ArgsWorld](https://arxiv.org/abs/2611.28792)把输入视图与相机轨迹编码为可自回归扩展的显式 3D Gaussian 世界，目标不是只做一次前馈重建，而是让同一模型支持重建、从少量条件图生成、以及沿新相机轨迹继续外推。作者已公开[代码](https://github.com/M4A1TasteGood/ArgsWorld)与模型权重，输出 `world.ply` 和渲染视频。

当前路径要求 Linux、Python 3.11/3.12、支持 BF16 的 NVIDIA GPU、PyTorch、Wan2.2-TI2V-5B-Diffusers 与 `gsplat==1.5.2`。生成和外推以最多 24 个相机为一段继续推进，因此长轨迹的误差累积、接缝与显存都要自行测量；仓库顶层许可没有在本期取得清晰声明，上游模型条款也需分别核对。

**编辑摘要：** ArgsWorld 的新闻价值在于把显式可渲染高斯变成可连续扩展的世界状态，并提供了可运行权重；它仍是重型 NVIDIA 研究管线，不能仅凭统一任务描述视为生产级世界模型。

**判断：P1/P2 研究原型，代码+权重可跑；可信度 A/B。适合选一条 24 帧内轨迹和一条跨段长轨迹，分别记录几何闭合、纹理漂移、生成时间与峰值显存。**

### Spirula 重构数据集创建界面，并把顺序配对从隐式行为改成明确选项

Spirula Studio 在北京时间 11 月 25 日凌晨连续合并 [`0530582`](https://github.com/harry7557558/spirula-studio/commit/0530582a28c12bc0ef38a007cd6e02089c0d2b0d)、[`8aece78`](https://github.com/harry7557558/spirula-studio/commit/8aece782d346be3bbf2120ec7080327b136549d9) 与 [`7d728ff`](https://github.com/harry7557558/spirula-studio/commit/7d728ff1e2f469f5961c3f2c35ede87df6fc63f3)，重做数据集创建 GUI，并拆分过大的 `GuiApp.cpp`。SfM 的 PairMode 现在明确区分 prefilter 与 sequential：普通 prefilter 不再悄悄附带按文件顺序的邻帧，而只有显式选择 sequential 时才显示 overlap 与 loop closure。

GUI 的 mapper 选项改为与命令行共用同一张参数表，减少两套入口漂移；默认 100,000 帧上限被移除，`0` 表示不设上限，旧记录中的 100,000 会迁移为不限。取消上限不是内存变成无限，超大数据集仍需按特征数、匹配对和 VRAM/内存做预算。

**判断：P1 主干 SfM/GUI 行为修正；GPL-3.0；Vulkan/CUDA；可信度 B。升级主干后应重开旧工程，确认 PairMode、overlap、loop closure 与 frame limit 的迁移结果，再跑小规模重建对照；正式 release 尚未包含这些提交。**

### MaxSplat Studio 8.5.4 把 3ds Max 场景转成高斯 PLY

[MaxSplat Studio 8.5.4](https://jamiecardoso.gumroad.com/l/maxsplat-studio-3ds-max-gaussian-splat-glb?a=555385955) 是面向 3ds Max 的商业脚本，当前页面价格为 39.99 美元。它可自动处理几何与相机、按四个质量预设生成 PLY splat，并支持只处理选中对象或相机；分开的 GLB 工作流保留纹理，也声明兼容 rigging 与 animation。作者的[工作流文章](https://jamiecardoso.co.uk/jc_tutorials/maxsplat-studio-3ds-max-gaussian-splat-glb-v8-5-4/)提供一个约 675 MB 的 Corona 室内案例，并称可联系试用 7 天。

产品页同时写明转换“可能需要额外软件组件”，却没有列出完整 3ds Max 版本、GPU、训练器或云服务依赖；许可表述为软件授权而非出售。本期只核对公开页面，没有购买、安装或评测。**判断：P2 商业创作工具；researched、未 tested；可信度 B。购买前应先向作者确认自己的 3ds Max/渲染器版本、数据是否离机、输出属性和退款条款。**

### 三篇论文分别处理对象移除、冻结几何修正和半透明重光照

<!-- arxiv:2611.30102 -->

[LMnOP](https://arxiv.org/abs/2611.30102) 在不微调 3DGS 的条件下，用语言模型推理计划协调遮罩、深度与补全模块执行对象移除；作者报告在 3 个数据集、18 个指标中的 16 项领先，并给出 90%/99% 的移除成功率。**编辑摘要：** 它把对象移除从单一网络改成可计划的模块编排，但本期未找到官方代码，百分比也没有独立复现，现阶段属于论文方法而非可部署编辑器。

<!-- arxiv:2611.29236 -->

[Complementary Geometry / REVEAL](https://arxiv.org/abs/2611.29236) 不重训冻结的 Gaussian 模型，而是通过多视图重投影、共识与选择来修正深度，并提出 RGB-D 的 RIG 基准。**编辑摘要：** 这为“画面看起来对、深度却不能用”的既有 3DGS 提供后处理方向；公开材料覆盖 6 个 backbone 和 3 个 benchmark，但本期未找到官方代码。

<!-- arxiv:2611.30351 -->

[NNS-GS](https://arxiv.org/abs/2611.30351) 针对半透明物体，把非局部散射与校准点光源纳入 Gaussian 表达；作者报告相对基线在合成集平均提升 2.47 dB、真实集提升 0.81 dB PSNR。**编辑摘要：** 论文把半透明介质的长程光传输纳入可重光照高斯，但实验依赖受控光源标定，且本期未找到代码，不能直接迁移到普通手机扫描。

三项目前均为论文无代码，作者数字未独立复现。**判断：P2 研究信号；可信度 A（论文存在）/B（作者实验结论）。**

### SemGuard 用几何、外观和跨帧一致性检测高斯渲染攻击

<!-- arxiv:2611.28636 -->

[SemGuard](https://arxiv.org/abs/2611.28636) 研究针对 3D/4D Gaussian 渲染结果的语义对抗攻击检测，把几何偏差、外观异常和时间一致性组合起来。作者已经公开[代码](https://github.com/shisyy/SemGuard)和处理后的渲染资产，环境示例为 Python 3.12、CUDA 12.1、PyTorch 2.5.1，并依赖 graphdeco 3DGS、4DGaussians、CLIP 与 Diff-JPEG。

**编辑摘要：** 这是少数已经给出复现实物的高斯安全论文，适合做检测研究基线；仓库顶层许可与多个上游依赖许可仍需审计，资产也不是完整训练数据，不能直接标记为生产安全产品。

**判断：P1/P2 研究原型，代码与处理资产可测试；可信度 A/B。**

### RadioWorld、SpectralGS 与 AdvMTO 把高斯扩到无线电、光谱和自动驾驶攻击

<!-- arxiv:2611.29282 -->

[RadioWorld](https://arxiv.org/abs/2611.29282) 用 RF radiance field 表示城市无线传播，并提出 UrbanRF-Bench，作者称包含 7 个城市、657 个场景和 32,850 个场；代码、数据与 checkpoint 仅承诺在接收后发布。**编辑摘要：** 它把“可渲染场”从可见光迁移到无线电传播预测，行业潜力大，但目前只有论文和待发布承诺。

<!-- arxiv:2611.29388 -->

[SpectralGS](https://arxiv.org/abs/2611.29388) 用共享光谱与局部空间 Gaussian 从 RGB 做无监督高光谱重建，并显式估计相机光谱响应。**编辑摘要：** 论文尝试把高斯用作连续光谱表示，而不是三维点云；本期未找到官方代码，传感器跨域稳定性仍需验证。

<!-- arxiv:2611.30283 -->

[AdvMTO](https://arxiv.org/abs/2611.30283) 基于 2D Gaussian Splatting 生成跨模态、跨时间的物体级对抗攻击，目标是 BEV 三维检测器，并在 nuScenes 上评估。**编辑摘要：** 这是自动驾驶安全研究，不是新的场景重建器；没有公开代码时，不能把作者攻击成功率外推到其他传感器和检测栈。

三项均为论文无代码或尚未发布代码。**判断：P2 跨领域研究信号；可信度 A/B。**

### 两篇稀疏视图论文分别从梯度冲突和方向曲率修正几何

<!-- arxiv:2611.28111 -->

[GC-GS](https://arxiv.org/abs/2611.28111) 把多视图梯度冲突视为几何错误信号，在不引入额外网络监督的情况下调整优化；论文已标注 WACV 2027。**编辑摘要：** 它把训练中通常被当作噪声的冲突转化为几何诊断，但本期未找到官方实现，属于迟到索引补收。

<!-- arxiv:2611.28802 -->

[Not All Directions Are Flat](https://arxiv.org/abs/2611.28802) 从方向相关曲率出发，讨论稀疏视图下 Gaussian 过度扁平和几何退化。**编辑摘要：** 方法把“所有方向都按同一平坦先验处理”的问题拆开，理论上更适合薄结构和斜视角；没有代码与统一硬件数据时仍应作为研究线索。

**判断：P2 论文无代码；可信度 A/B。**

## 相关深读与行动建议

1. **Unreal 团队优先试 OpenSplat4D。** 选三种不同资产格式，分别记录导入时间、GPU 内存、排序稳定性、4D 播放、阴影、碰撞、打包和许可证清单；不要先用作者演示替代自己的真实资产。
2. **Vizrt 团队把“可导入”与“可播出”分开验收。** 测试 SOG/PLY 多 LOD、摄像机切换、虚拟灯光、色调映射、前景合成和长时间播出；镜面、玻璃、动态物体与物理交互预先列为非目标。
3. **PlayCanvas 项目不要给含 splat 的相机开启 reverse-Z。** 先在纯 mesh 大场景验证深度收益；待 Gaussian projection、scene depth、picker 与 XR 都有明确上游覆盖后，再考虑混合场景。
4. **WildAnySplat 与 ArgsWorld 都要先审上游许可。** 前者涉及 VGGT-Omega，后者涉及 Wan2.2；代码仓库可访问不等于整条模型链可商用。
5. **Orbit 的 4DGS beta 用短片段做门槛测试。** 先确认同步方式、相机数量、显存、训练时长和播放器输出，再决定是否投入长素材。
