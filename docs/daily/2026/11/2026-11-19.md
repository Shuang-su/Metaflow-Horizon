# Horizon 行业日报 — 2026-11-19

> **增量窗口（北京时间）**：2026-11-18 08:35:00—2026-11-19 08:50:00；同时回查 2026-11-12 以来的迟到索引与更正，并与尚未合入主线的 11 月 17、18 日稿件去重。本期逐项区分正式发行、公开研究发布、仓库主干和媒体发现；未实际运行软件、复现实验或验收设备。

## 速览

今天的头条是两条不同方向的“进入实际系统”信号。亚利桑那州立大学（ASU）公开 [Open4DGS](https://open4dgs.asunemlabs.com/)：它不要求硬件 genlock（多机位共用精确时钟）或全局快门，而是从画面运动估算亚帧时间偏移与滚动快门读出，再训练动态高斯。代码、受限测试数据和完整七阶段流程已经上线，但仓库明确称其为**初始研究发布**，分拆仓库还没有完成一次仅依赖公开版本的全新端到端 GPU 验证。

另一条来自 [ArcGIS Reality Server](https://www.esri.com/arcgis-blog/products/arcgis-reality-server/imagery/arcgis-reality-server-is-now-available)。它随 ArcGIS Enterprise 12.2 正式 GA（一般可用），把包括 Gaussian splat 在内的无人机、航空与卫星影像产品放进可自托管、可横向扩展的企业 GIS 处理链。这不是新查看器，而是从任务管理、分布式计算到 Python/REST 自动化的生产后端；价格未公开，生成高斯还带来明确的 NVIDIA、CUDA 与内存门槛。

工具主干也在扩展输入与几何出口。Spirula 同一天合入 2DGS surfel 训练、TSDF 网格化、显存友好的 OpenGL 硬件栅格器和 Voronoi 分区；LichtFeld 则把 360° 全景与超广角鱼眼拆成多个针孔视图训练，并在显存不足时延后自动保存而不是让后台快照拖垮训练。它们都没有对应新 tag，适合锁提交做小样验证，不应描述成正式版功能。

## 重点正文

### Open4DGS 试图用视觉同步取代昂贵的多机位 genlock

[Open4DGS 项目页](https://open4dgs.asunemlabs.com/)和两个公开仓库把流程拆成 [Open4DGS-Core](https://github.com/ASU-NEM-Labs/open4dgs-core) 与 [Open4DGS-Trigs](https://github.com/ASU-NEM-Labs/open4dgs-trigs)。Core 负责帧与 timecode 提取、COLMAP 标定、BGMv2 / SAM 2 抠像、亚帧同步、RoMa v2 跨视角匹配、MEMFOF 时间跟踪和导出；Trigs 在 TRiGS / TriGSVanilla 基础上训练连续时间的动态高斯。Core 是 MIT，训练器是 AGPL-3.0；[示例数据](https://huggingface.co/datasets/asu-nem-labs/open4dgs-datasets)另有只允许私人、非商用评估的许可，不能把代码许可套到人物素材、渲染或重建结果上。

关键变化在采集门槛。`calculate-sync.py` 用跨相机极线运动估计每台相机的连续时间偏移，并把传感器逐行读出写成滚动快门项；闭环一致性不足时会回退到 timecode 基线。初始化阶段根据点的运动速度插入一帧宽度的 sub-keyframe，训练时再给快速运动帧增加采样次数。项目页在 27 相机、60 fps 的 `apt-dance-01` 片段上报告：快速帧 108 个 held-out 视图的 PSNR 从 31.69 dB 增至 34.18 dB。这个数字只比较项目自己的均匀采样与加权采样，不能外推成相对其他 4DGS 的通用优势。

当前可操作边界同样重要。文档验证过 Ubuntu 24.04、Python 3.11、CUDA 12.8 与 RTX 3090，另记录 Windows 11 / RTX PRO 6000 Blackwell 的报告配置；WSL 2 未验证。仓库明确说分拆后的依赖覆盖与包构建已通过，但尚未完成只用两个公开仓库的全新端到端 GPU 跑通。`.trigsbin` 保存完整场景张量，是工具间的中间格式，**当前不可流式传输**；压缩、流式、Unity、Web SDK 与 8th Wall 都只是没有承诺日期的 roadmap。每帧 PLY 可以进入 Blender、Unreal 或 WebGL，但不能因此推断已有跨工具实时播放管线。

这条发布的现实价值，是让高校、独立团队能够先用 GoPro、Sony action camera 或混合消费机位试验 4D 捕获，而不必先购买广播级同步系统。首轮测试应从公开数据和 3—5 秒快速动作开始，分别记录同步回退、滚动快门读出参数、标定误差、系统内存、显存、训练时间与人物边缘；没有这些条件的“+2.5 dB”比较没有可迁移性。**判断：P0/P1 开放采集工作流；初始研究发布、可实际测试但尚非生产可用；可信度 A/B。**

### ArcGIS Reality Server 把高斯生成接进自托管企业 GIS 后端

[Esri 于 11 月 17 日宣布](https://www.esri.com/arcgis-blog/products/arcgis-reality-server/imagery/arcgis-reality-server-is-now-available)，ArcGIS Reality Server 随 Enterprise 12.2 从 beta 进入 GA。它把无人机、航空和卫星影像分发到多台服务器，输出可以包括 true ortho、DSM/DTM、点云、网格和 Gaussian splat；容量通过增加机器扩展，多名用户通过 project / mission 与成员权限协作。对受数据驻留、合同或安全要求约束的机构，影像和计算可留在自管基础设施或私有云，而不是必须上传厂商托管服务。

这一变化的新闻价值不只是“Esri 能看 splat”。桌面端 ArcGIS Reality Pro 可以建立项目后提交服务器，ArcGIS API for Python 与 REST API 能自动化重复任务，Reality Web App 则以 beta 形式提供浏览器任务管理、处理与分享。也就是说，高斯第一次在这条产品线上成为可排队、可治理、可扩展的企业产物，而不是单机应用导出的孤立文件。

部署成本不能省略。Esri 的系统要求显示，Reality Server 站点中每台参与 Gaussian splat 处理的机器至少需要 64 GB 内存、计算能力 7.5 以上且至少 8 GB 显存的 NVIDIA GPU、CUDA 13 或更新版本，并安装 Deep Learning Libraries。官方没有公开价格，要求联系客户经理；Web App 仍是 beta。下游仍要按 ArcGIS 的 3D Tiles / glTF 扩展兼容链验证，而不是假定任意 PLY 查看器可以直接消费服务器结果。

如果团队已经用 ArcGIS Enterprise 管理航测影像，这次 GA 值得用一处中型工地或园区做并行试点：同时生成 mesh 与 splat，比较提交、队列、失败恢复、权限、制品大小、视图质量和现有 Web Scene/数字孪生应用接入。若只是个人扫描或单机创作，它的服务器、许可与运维门槛不会比桌面工具更轻。**判断：P0 企业级生产链正式落地；闭源商业产品；可信度 A。**

### Spirula 主干一次补上 2DGS、TSDF 与更低显存的显示路径

[Spirula Studio 提交 `5806955`](https://github.com/harry7557558/spirula-studio/commit/5806955241ec653a1ba279cf2e73dc17e6d03cba)把 2DGS surfel 原语和 `spirula mesh --method tsdf` 合入主干。2DGS 在 CUDA 与 Vulkan 后端共用 Slang 定义的 ray-disc 求交，支持 RGB、深度与法线输出，并复用 3DGUT 的投影反向与 fused optimizer；GUI、CLI 和 13 种语言的帮助也一起接入。作者在一个 action-camera 鱼眼数据、7000 steps、100 万 splat 的条件下报告 2DGS 为 23.91 dB，3DGS 为 24.43 dB，3DGUT 为 24.26 dB；训练时间约为 3DGUT 的 1.3 倍。数字说明这是几何/网格取向的折衷，不是画质与速度同时无条件提升。

TSDF 路径从每个训练相机的中值深度融合稀疏体素，再用 marching tetrahedra 提取零等值面，最后复用原有清理、定向和贴图链。作者自己的 action-camera 对照中，2DGS 模型用 TSDF 的 F-score 0.682，opacity field 为 0.693；在 3DGS 模型上 TSDF 反而是 0.474，对比 opacity field 的 0.562，原因是多相机深度平均更容易保留浮点。因此 GUI 的建议是优先给 2DGS 选择 depth fusion，而不是把 TSDF 设成所有模型的新默认。

同一窗口还有 [`303d1c6`](https://github.com/harry7557558/spirula-studio/commit/303d1c6fdfaeaab1d604b18a78c7063a38dd7135) 的 OpenGL 硬件栅格器回退、[`b631f11`](https://github.com/harry7557558/spirula-studio/commit/b631f114964dd9e0bc207972ca7af4ac49b5ce66) 的 Voronoi 分区，以及 [`9714586`](https://github.com/harry7557558/spirula-studio/commit/97145860684c1604ef0ad978c3da657f0aecaf05) 对渐进分辨率显存预测与降采样缓存的改进。项目为 GPL-3.0；这些都是主干提交，当前没有证据表明它们已经进入新的正式 release。**判断：P1 可锁提交测试；优先验证 2DGS→TSDF 网格和低显存查看，不要跨数据集转述作者指标；可信度 B。**

### LichtFeld 让全景与超广角鱼眼进入常规训练器

LichtFeld Studio 的一组连续主干提交扩展了镜头输入。[`979ed5d`](https://github.com/MrNeRF/LichtFeld-Studio/commit/979ed5dee72e692150f2fa9072c60ef37d967cc7) 把一张等距柱状 360° 全景切成六个针孔视图，用现有快速栅格器训练；深度图按射线距离监督，法线被旋转到各视图坐标系，但工程仍保留“一张照片一个相机”的身份。[`db400bc`](https://github.com/MrNeRF/LichtFeld-Studio/commit/db400bc3ff81110c897857cb307e20568e695cd5) 对看见半球或更多范围的鱼眼切成五个针孔视图，较窄鱼眼继续走单张去畸变视图；[`fa05c80`](https://github.com/MrNeRF/LichtFeld-Studio/commit/fa05c8022a2f2e2c73df3fd6887d169ebe334e8e)则在相机优化时让同一照片派生的视图共享一套 pose，避免把切片错误地当成多台相机各自漂移。

另一项 [`7357983`](https://github.com/MrNeRF/LichtFeld-Studio/commit/73579832efa8c08c92f175708bd105d1a1ada987) 在显存不足时延后后台 splat 自动保存，并保留已经部分捕获的数据、只提示一次内存错误。它降低快照任务挤占训练显存的风险，却不等于保存一定完成；无人值守训练仍要把“deferred snapshot”纳入失败监控。项目为 GPL-3.0，上述变化均在主干，没有新的正式 tag 证据。

对 Insta360、双鱼眼或超广角素材，这批改动值得用同一数据比较三条路线：原始全景/鱼眼切片、外部预先去畸变、旧针孔近似。至少记录 pose 一致性、接缝、视场边缘、深度/法线监督、显存和最终 PLY/SOG/SPZ 导出；只有主干跑通后再决定是否进入长期项目。**判断：P1 主干工程更新；可实际测试、尚未发行；可信度 B。**

### Pentimento 获奖说明 splat 正在承载“为什么现场会偏离 CAD”

<!-- arxiv:2606.19609 -->

[Building Drift: Documenting On-Site Construction Adaptations Across Material Lifecycles](https://arxiv.org/abs/2606.19609)（arXiv:2606.19609）于 6 月首发、10 月更新并在 ACADIA’26 获 Best Paper；[Cornell 11 月 17 日公告](https://news.cornell.edu/stories/2026/11/tracking-flaws-used-building-materials-facilitates-reuse)让这项早先论文成为本期补收的应用新闻。Pentimento 用手机或 Meta Ray-Ban 录视频和现场讲述，COLMAP 估计相机，gsplat 生成场景，再靠 ArUco 标记把 Gaussian splat 注册到 glTF 设计模型；转录和分类把“施工为何改变”挂回空间与时间位置。

它的重要性不是新的渲染指标，而是把 splat 用作回收木材施工记录的空间索引。论文没有公开代码，评估以案例与定性观察为主，也没有用户研究；因此更适合作为建筑 HCI 的获奖原型，而不是可采购的施工管理产品。**判断：P2 获奖研究与行业应用；论文无代码；可信度 A。**

## 相关深读与行动建议

1. **先跑 Open4DGS 的公开样例，再碰自己的相机。** 固定一个短动作片段，检查 timecode、视觉同步置信度、rolling-shutter readout 与回退报告；记录 Core、Trigs 两个提交 SHA 和模型权重版本，避免把分拆仓库的安装差异误判为算法问题。
2. **企业航测用户评估 Reality Server 的“完整任务成本”。** 除 GPU 时间外，同时记录队列等待、失败重试、多人权限、制品存储、ArcGIS Pro / Web App / API 三种入口和 mesh 对照。没有 Enterprise 12.2 与对应许可的团队不必为了生成一个 splat 搭建整套服务器。
3. **Spirula 把 2DGS 与网格出口成对测试。** 2DGS preset、普通 2DGS、3DGS 各跑一组，再分别用 opacity field 与 TSDF；同时看渲染 PSNR、网格 precision/recall/F、时间、RAM、显存与 floaters，不只看单个 F-score。
4. **LichtFeld 的全景切片要重点看共享 pose。** 用可见接缝和已知直线/垂线场景验证六视图/五视图之间的几何一致性，并模拟显存不足确认延后 autosave 是否被监控系统正确捕获。
