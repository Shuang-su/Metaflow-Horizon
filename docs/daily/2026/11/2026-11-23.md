## 重点正文

### PlayCanvas 用引用计数缓存修复 SOG 分块场景的共享纹理生命周期

[PlayCanvas Engine 提交 `9ce5b4d`](https://github.com/playcanvas/engine/commit/9ce5b4de061358d761440ebf79d7bc9645734fc4) 于北京时间 11 月 23 日 04:52 合入主干，对应 [PR #10110](https://github.com/playcanvas/engine/pull/10110)。问题发生在多个 SOG 文件的 `meta.json` 指向同一个纹理 URL 时，例如一组 LOD 或空间分块共用一张球谐调色板。旧路径虽然能复用加载器缓存中的纹理对象，但每个 SOG 资源仍把它当成自己所有；卸载任一文件会销毁纹理，其他仍在场景中的文件随后可能读取已销毁资源。

新建的 `SogTextureCache` 以应用为边界、按 URL 保存 Promise、纹理对象和引用数：第一次请求触发下载，后续文件共享同一次加载和同一个 GPU texture；最后一个引用释放后才销毁。实现还处理了资源在网络加载完成前被释放、随后又被重新引用的竞态，并补充相应单元测试。它不是通用的所有 GPU 资源缓存，也不会自动把任意 SOG 变成 LOD；实际受益对象是已经把多文件组织成共享纹理、分块或 LOD 的项目。

对编辑器导出、Viewer 与自定义 PlayCanvas 集成而言，这项修改首先改善卸载、切换和流式加载的稳定性，也能避免同 URL 纹理的重复下载和重复 GPU 分配。现有 SOG 资产本身不需要因这项修复重编码，早期 SOG v3 资产问题也不能被泛化为“所有用户必须全量升级”。当前没有包含它的新 Engine release；建议锁提交做“加载 A/B、卸载 A、继续渲染 B、重新加载 A”的回归，再等待正式 tag。**判断：P1 运行时稳定性修复；MIT；主干可测试；可信度 B。**

### Ink Studio 把 splat 当作程序化像素体积的创作媒介

[Ink Studio](https://github.com/siliconjungle/shapeshift-labs-ink-studio) 是 Shapeshift Labs / Silicon Jungle 开放的 MIT JavaScript 工具包，本期按 7 日重查补收。它不是扫描训练器，而是从 SDF（有符号距离场）实体开始，采样和烘焙像素化 Gaussian splat，再加入动画、碰撞反应、破碎、生长、持久化、角色、粒子和程序生成。Node CLI 提供 CPU 渲染，浏览器路径使用 WebGL 2；场景可以用 JavaScript 或 JSON 描述，也支持网格、深度图输入和 GLB 导出。

当前安装路径是 `npm install github:siliconjungle/shapeshift-labs-ink-studio`，要求 Node.js 18+。仓库的 `package.json` 标记为 private，未核实到 npm 正式发布或 GitHub release；浏览器宿主也需要自己提供 UI 和场景管理。GitHub 页面在核查时显示约 1,000 Stars、86 forks 和超过 1,190 次提交，这说明关注度和开发频率较高，却不能替代兼容性、长期维护和性能测试。

它对高斯工作流的新价值在于，把“拍摄—重建—编辑”之外的直接创作路径做得更完整：几何、材质、灯光、动作和交互行为都能在同一脚本场景中生成。不过公开示例不等于通用编辑器，CPU 与 WebGL 2 两条渲染路径也需要分别验证。**判断：P1 早期创作工具；MIT；可实际测试；可信度 B。适合先用一个小场景核对导出、浏览器帧率和资产许可，不宜按成熟 DCC 替代品采购。**

### Spirula 把超大 Delaunay 网格化与三分类遮罩推进主干

Spirula Studio 的提交 [`9578f5a`](https://github.com/harry7557558/spirula-studio/commit/9578f5a6bfcf8416fb1bfbfe4e2808c531108593) 将 Delaunay 管线的索引改为 64 位，并把代码上限从 1.5 亿点提高到 5 亿点。界面和 CLI 会先按约 300 bytes/point 预测内存，结合可用 RAM（Linux 计入 swap）提前拒绝明显放不下的任务；提交 [`09d1462`](https://github.com/harry7557558/spirula-studio/commit/09d146228f11616327505037390de9c0fa1dcf8c) 又增加每个 Gaussian 取 1 或 7 个样本的选项，用较少样本换取更低网格化负担。

这只是数据结构、内存门槛和参数范围的扩大，不是作者已经证明 5 亿点能在普通工作站完整跑通。按代码估算，5 亿点仅核心工作集就接近 150 GB，此外还存在容器、系统和输入开销；真正可用上限受 RAM、swap、点分布和并行开销限制。使用这条路径时，应先在代表性子集上记录峰值内存和拓扑质量，再逐档扩大。

提交 [`ee2934f`](https://github.com/harry7557558/spirula-studio/commit/ee2934f92af0a57f69195c2fb1c3865caca160da) 同时加入 `segment_and_ignore` 三分类遮罩：前景参与重建，背景提供约束，忽略区不计入训练。它比二值前景遮罩更适合动态遮挡、反光或不可靠区域，但遮罩生成质量会直接影响监督边界。上述变化都是 GPL-3.0 主干提交，正式版没有同步更新。**判断：P1 大场景与训练控制改进；Vulkan/CUDA；锁提交可测试；可信度 B。**

### Animated SOG 新增逐帧关键帧的稠密 flipbook 配方

[Animated SOG 提交 `05364cf`](https://github.com/arrival-space/animated-sog/commit/05364cf2641ce80a95b12888625714b2657d467c) 是 11 月 21 日首次归档后的实质增量。新的 `asog flipbook train/run --recipe dense` 把每一帧都设为关键帧，允许短而自由的 Gaussian 生命周期，使用随机 thinning，不做 relocation 和 opacity regularizer，并增加裁剪、轨道相机、`--head-boost` 与透传训练参数。它依赖 Arrival.Space 的 `open4dgs-trigs` 分支；仓库自身为 MIT，但上游训练代码及数据仍需分别核对许可。

作者在仓库中报告：一段 2.2 秒篮球片段约 98 万 splats，逐 16 帧、逐 4 帧和逐帧留出设置分别得到 29.4、36.4、41.8 dB；另一轮重训把样例从 30.0 MB 降到 27.0 MB，并改善作者选取的面部近景。这些数字受片段、相机、裁剪、采样和评估切分影响，本期没有复现，不能拿来与静态 3DGS 或其他动态方法直接横比。

密集配方的价值是给短片、快速动作和遮挡变化一个简单基线，代价是时间冗余和逐帧关键帧体积。配套比较 viewer 的共享相机、时钟、近景框选和慢放也连续修复，但都没有正式 release。**判断：P1 动态高斯研究工具；代码可测试、权重与通用基准边界有限；可信度 B。**

### VideoRNG 把视频先验、前馈高斯与可重光照外观接成一条生成链

[VideoRNG（arXiv:2611.25338）](https://arxiv.org/abs/2611.25338) 于 11 月 19 日提交，本期按迟到索引补收。方法先用视频生成器从文本或单张图像产生已知相机和光照条件下的结构化 RGBA 转台，再从视频 VAE latent 前馈重建数百万各向异性 Gaussian；共享方向解码器与随机 Gaussian ray tracer 输出可随观察与光照方向变化的神经外观。作者把毛发、羽毛和蛛网等难以稳定网格化的细结构列为目标对象。

这条路线的重要性不在于“又一个图生 3D”，而在于把生成视频里的多视图与光照信息留到显式高斯资产中，并把反射外观与几何表示分开。论文还描述前景 token 选择与按成本分布采样，以控制大规模高斯预测。不过目前只核实到[论文](https://arxiv.org/abs/2611.25338)和[项目展示仓库](https://github.com/videorng/videorng.github.io)，没有找到可运行训练或推理代码、权重和独立复现。

因此它现在适合跟踪表示和数据管线，不适合列入可部署工具清单；演示质量也不能替代公开基准、运行成本与资产可编辑性。**判断：P2 论文突破；论文+项目演示、无代码；可信度 A/B。**

LichtFeld Studio 提交 [`f6d3885`](https://github.com/MrNeRF/LichtFeld-Studio/commit/f6d3885bba3993a29acb8dfcc5e758baa9b2c2ae) 把 portable 可执行文件放到包根目录，DLL 与运行时整理进 `bin`，并用私有 assembly manifest 与新的资源定位方式保持插件、图标和 MCP 自动启动可见；提交 [`a40b6f3`](https://github.com/MrNeRF/LichtFeld-Studio/commit/a40b6f3f49417b10c3c847461080f283dff650f4) 避免 Windows 第三方许可证读取停顿或重复读取。它改善部署和启动，不改变训练或渲染质量；两项都只在 GPL-3.0-or-later 主干，尚无对应 release。**判断：P1 工程可用性改进；可信度 B。**

### 6 平方公里 Randers 作品把 6 亿高斯带进 SuperSplat

[SuperSplat 作品页](https://superspl.at/scene/cbf5b0c9)标注该 WIP 场景覆盖丹麦 Randers 约 6 km²，包含 606.8M splats、页面资产约 9.39 GB，并允许切换到 8M、16M 等细节档。素材说明把 2025 年航摄影像归属 Klimadatastyrelsen、许可列为 CC BY 4.0；作品由 Guldmund 独立制作，不代表数据机构背书。

作者在 [Reddit 原帖](https://www.reddit.com/r/GaussianSplatting/comments/1y2tru8/randers_600_million_gaussians/)中称使用自研非 Adam 引擎，按 250 m cell 和 1 km tile 并行处理，再做接缝与亮度统一。这是作者公开说明而非独立复现，不能据此推导训练成本或普适上限；但在线作品本身为大范围航摄高斯的 LOD、分块和浏览器交付提供了可直接观察的案例。**判断：P2 作品与工程信号；在线可查看、训练工具未开放；可信度 A/B。**

## 相关深读与行动建议

1. **SOG 流式项目先测纹理生命周期，不必重编码全部资产。** 用两个引用同一纹理的 SOG 文件做加载、卸载、并发取消、重新加载和显存观察；正式版项目保留当前 tag，对主干修复单独建回归分支。
2. **Ink Studio 用最小场景验证“创作—导出—播放”闭环。** 固定一个 SDF 角色、一段动画和一个交互反应，记录 CPU 与 WebGL 2 输出差异、导出 GLB 的可携带性、浏览器帧率和第三方资产许可。
3. **Spirula 的 5 亿点是代码上限，不是硬件承诺。** 从 1000 万点开始逐档记录 RAM、swap、耗时和网格质量；三分类遮罩另做边界消融，避免把忽略区造成的空洞误判成网格化问题。
4. **Animated SOG 与 VideoRNG 分开评估。** 前者现在有可运行代码，适合短片和 viewer 管线实验；后者仍是论文/演示，应等待代码、权重和成本条件，不要把演示资产列为可交付格式。
