## 速览

今天最值得关注的是 4D 高斯第一次出现一套面向网页交付、同时公开格式规范和播放器实现的新容器。[Arrival.Space 的 Animated SOG](https://github.com/arrival-space/animated-sog) 用单个 `.asog` 文件保存运动高斯、球谐和可选音频，仓库同时提供 Python 编码器、流式 JavaScript 解码器、PlayCanvas 与 Three.js 播放器。它不是 SOG v3 的升级，也不是通用 4DGS 标准：v1 沿用 SOG v2 的静态属性压缩，运动模型来自 TRiGS，播放器还依赖 PlayCanvas 2.22 的少量内部接口。

制作工具侧，LichtFeld Studio 主干把“找出模糊相机”从人工翻图变成可并行执行的筛选流程，并补上 Save As 后外部数据路径的可移植性；Spirula Studio 则改进 3DGUT/2DGS 的 Gaussian—tile 相交和剔除。两者都没有新 release，适合锁提交验证，不能写成已正式发行。

商业应用出现一条更清晰的建筑现场口径。VDC Viewer 官方公告给出了月费 5 万日元起、数千万点级 3DGS、BIM/360°/二维图纸叠加、测距测面积以及 14 种高斯和三维格式的范围。它把“浏览器能打开 splat”推进到组织、项目、权限和国内数据存储，但性能与厘米级测量仍是厂商陈述，本期没有实测。

研究方面，PaveSplat 不只是论文：代码、两个 ViT-L 权重、复现脚本和依赖边界已经公开；AGSR、CryoGaussian 与 MergeableRF 则分别把高斯带到推理期超分、异质冷冻电镜与参数合并式重照明。后三者目前没有找到可运行的作者代码，新闻价值不低，但可行动程度不同。

## 重点正文

### Animated SOG 把 4D 高斯做成可流式播放的单文件

[Animated SOG 仓库](https://github.com/arrival-space/animated-sog)于 11 月 20 日创建，定义 `.asog` v1：每个 splat 在有限时间内存活并按刚体轨迹运动，静态属性沿用 SOG v2 的 16 位对数位置、smallest-three 四元数、256 项码本和 SH 调色板，运动则量化为固定的 17 值表达。一个文件可以同时携带球谐和音频；JavaScript 解码器支持边下载边解码，PlayCanvas 播放器覆盖 WebGPU/WebGL，Three.js 播放器覆盖 WebGL 2。

仓库给出的 Charlie 样例从 319 MB 的 TRiGS 运行时文件降到 28 MB，质量约 45 dB；一个 180 帧、原始 PLY 共 3.6 GB 的 flip-book 样例，逐帧 SOG 为 202 MB，`.asog` 为 8.6 MB。900k splat 的样例在作者 RTX 5080 桌面上约 0.9 秒可用。这些都是作者在指定资产和硬件下的测量，不能直接推成“所有 4DGS 都压缩 11 倍”或移动端性能结论。

输入端有两条路径：现成 TRiGS `.trigsbin` 可以直接编码；逐帧 PLY 则要调用外部 Open4DGS 做 distillation，需要 CUDA GPU。Animated SOG 本身为 MIT，但 Open4DGS 是独立的 AGPL-3.0 组件；README 指向 PyPI/npm 的安装命令，核对时仓库没有正式 GitHub release，因此生产项目应锁 commit 和依赖版本。它的现实价值是把 4D 内容交付从“帧文件夹或专用播放器”变成可缓存、可渐进下载的网页资产；限制是只覆盖一种运动模型、尚未形成跨厂商规范，并依赖少量 PlayCanvas 内部 API。**判断：P0/P1 新格式与可运行工具链；可实际测试；可信度 A/B。**

### LichtFeld 主干加入模糊相机筛选，并修复项目迁移路径

[LichtFeld 提交 `55a0c6e`](https://github.com/MrNeRF/LichtFeld-Studio/commit/55a0c6e4235a0d5aa8e6f48a3c9291898aa256f0)在相机选择中加入 Select Blurry；[`a5b49d2`](https://github.com/MrNeRF/LichtFeld-Studio/commit/a5b49d2c67174eb6c3b8431ac8c7bd3060740956)把 CPU 清晰度评分并行化，[`ea3ab51`](https://github.com/MrNeRF/LichtFeld-Studio/commit/ea3ab5181fd1cd03ac951304d67a21d64838c73b)缓存同一项目会话中的评分并显示扫描进度，[`3d138e7`](https://github.com/MrNeRF/LichtFeld-Studio/commit/3d138e7583a39384539ae25da3a62863a81ab17f)又让已驻留在 GPU 的视频帧先在 CUDA 上评分，避免为了检测模糊而完整回读 RGB。随后 [`6dc7483`](https://github.com/MrNeRF/LichtFeld-Studio/commit/6dc7483a27da37f11b765a69c28d8a76f8c7481a)补上缺图处理和回归覆盖。

这组提交改善的是数据清洗入口，不是新的清晰度模型或训练算法。它能让数百到数千张输入先按评分筛一遍，减少人工检查和模糊帧污染；但自动选择仍可能把运动模糊、景深虚化和低纹理区域混在一起，真正删除或排除相机前仍要抽样复核。

同一批主干提交还处理项目可移植性。[`719f363`](https://github.com/MrNeRF/LichtFeld-Studio/commit/719f36356c159dfabc7c75ce04be5d9c43d4a711)让首次 Save As 后，与项目相邻的数据集继续使用可移动引用；此前两个提交分别恢复嵌入数据与迁移外部数据的相机路径。对跨机器、外置盘和归档项目而言，这比界面功能更接近数据完整性修复。项目为 GPL-3.0，当前变化均在主干、没有新 tag。**判断：P1 数据清洗与可靠性更新；锁提交可测试；可信度 B。**

### VDC Viewer 给出面向建筑现场的产品、格式和价格边界

[株式会社 VDC 的 11 月 20 日公告](https://prtimes.jp/main/html/rd/p/000000001.000194723.html)确认，VDC Viewer 是 2026 年 10 月上线的云端服务，月费 50,000 日元起，面向 PC 与平板。它把 3DGS、BIM/网格、360°全景、DXF 图纸和普通图像放在同一空间中，提供多模型叠加、距离与面积测量、三维注释、URL 分享、项目权限、MFA/SSO 和日本境内数据存储。

官方列出的高斯格式包括 `.ply`、`.compressed.ply`、`.sog`、`.splat`、`.ksplat`、`.spz`、`.mjs`、`.lcc` 与 `.lcc2`；网格与设计数据还覆盖 GLB/glTF、FBX、IFC、USD/USDZ 等。公告称自动优化可处理数千万点规模，并支持厘米级测量。这里的“数千万点”和“厘米级”都没有公开设备、网络、资产规模、误差样本或独立测量口径，本期应当按厂商能力声明记录，而不是性能验收结论。

它的新闻价值不是一个全新的渲染算法，而是把高斯交付和 BIM 复核放进企业权限、项目层级和现场协作。对建筑团队，现在可以预约演示并用真实项目检查上传转换时间、首屏与漫游帧率、平板性能、坐标对齐、量测误差、版本保留和数据退出机制；对开源开发者，它是闭源商业服务，不能与可嵌入 viewer 混写。**判断：P1 商业 AEC 产品；正式公告、未实测；可信度 A。**

### Spirula 修正 3DGUT/2DGS 的 tile 相交和剔除

[Spirula 提交 `254eb5e`](https://github.com/harry7557558/spirula-studio/commit/254eb5efd4561c314604855c407fc1a83a478d20)改进 3DGUT 与 2DGS 的 Gaussian—tile 相交和 culling。它发生在 11 月 20 日 17:44 UTC，晚于昨天的增量窗口，是 11 月 19—20 日 2DGS、TSDF 和网格质量改动的后续修正，而不是另一套新 primitive。

对屏幕空间 tile 渲染器来说，相交测试过松会把不贡献像素的 splat 带进排序和光栅阶段，过紧则会裁掉边缘贡献。这个提交值得用近裁面、大椭圆、斜视 surfel 和广角/鱼眼相机做像素差与耗时对比；在作者没有给出完整发布基准前，不能把它直接写成明确百分比性能提升。仓库为 GPL-3.0，正式 release 仍未包含这批变化。**判断：P1 主干渲染正确性/效率更新；可信度 B。**

### PaveSplat 公开代码、权重和高分辨率复现实验

<!-- arxiv:2611.26045 -->

[PaveSplat](https://arxiv.org/abs/2611.26045)（arXiv:2611.26045）处理 feed-forward 高斯在更高输出分辨率下出现表面空洞的问题。常见方法从深度解析计算表面对齐协方差，训练分辨率下的一像素最小 footprint 会遮住朝向误差；放大到 2×—8× 后，错向 surfel 之间的缝隙才显现。PaveSplat 保留解析切平面作为初值，再学习一个单位四元数残差，只在需要时重新定向 surfel。

[作者仓库](https://github.com/janghunn/pavesplat)已经给出代码、PaveSplat/SurfSplat 两个 ViT-L 权重、SHA256、训练与评估脚本。测试栈是 Python 3.12、PyTorch 2.7.1+cu128、CUDA 12.8、GCC 13；训练论文配置使用两张 GPU、有效 batch 32 和 150k optimizer steps，评估用单卡。数据涉及 RealEstate10K、ACID、DL3DV 与 ScanNet，并需额外下载 Depth Anything V2、GMFlow 和 DINOv2 权重。

代码许可为 CC BY-NC-SA 4.0，rasterizer 保留 research-only 许可，选定权重为 CC BY-NC 4.0，因此它是可复现研究发布而不是可直接进入商业产品的库。首轮测试最合理的是下载现成 ViT-L 权重，在同一 RE10K/DL3DV 样本上比较 1×、2×、4×、8× 的覆盖空洞、PSNR/SSIM/LPIPS、显存与速度；不要只用原生分辨率的小增益判断价值。**判断：P1/P2 代码+权重研究原型；可实际复现；可信度 A/B。**

## 简讯

### Quest 上的大场景交付出现“端侧 LOD”和“PC 串流”两条路线

[Radiance Fields 对 SplatBox 1.3 的记录](https://radiancefields.com/daniel-skaale-releases-splatbox-1-3-for-unity)称，Unity 插件加入分页 LOD、Burst 遍历、GPU 深度排序、固定显存图集和持久编辑/重照明；作者演示 730 万 splat 场景在 Quest 3 上加载。原始 X 帖本轮无法直接读取，商店页也没有独立 1.3 changelog，因此版本细节和 99.50 美元促销价属于媒体与作者转述，不能当作本期实测。

[Splatara Cloud Renderer](https://splatara.cloud/)走另一条路线：在 PC 渲染大场景，再通过局域网或 Tailscale 把结果串流到最多四台 Quest，并加入透视门户、共位和现实遮挡。社区帖子显示它也能连接云端 Shadow PC，但带宽、延迟、PC GPU、路由器和多头显同时决定体验。端侧 LOD 更适合离线与本地交付，PC 串流则用基础设施换更大资产，两者都需要在实际场地验收。**判断：P1/P2 商业 XR 路线信号；信息边界明确；可信度 B。**

### Splat Paint 与 Vintage Click 把高斯当作绘画和摄影媒介

[Splat Paint](https://github.com/remorses/splat-paint)把输入 PLY 变成附着在三维空间中的油画笔触，浏览器演示可以直接换入自己的 splat。仓库为 TypeScript，创建于 11 月 19 日，但没有声明许可证；现在适合看交互和表现，不适合直接复用到产品。

[Vintage Click 0.6.1](https://github.com/timfennell/vintage-click/releases/tag/v0.6.1)是 11 月 15 日发布、本期经迟到索引补收的 GPL-3.0 作品。它在高斯扫描中模拟 1970 年代手动相机、镜头与胶片，并把地面积雪重建成有体积的小 splat 表面；当前 0.6.1 只提供 Apple Silicon、macOS 15.2+ 构建，Windows 仍停在更早版本。两者的共同信号是，高斯正从“扫描结果”转成可编程的视觉材料。**判断：P2 创作作品与开源信号；可信度 A/B。**

### 三篇论文把高斯带到超分、冷冻电镜和重照明

<!-- arxiv:2611.25934 -->

[AGSR](https://arxiv.org/abs/2611.25934)（arXiv:2611.25934）在推理时收缩投影协方差，用多 aperture 渲染、置信度融合与深度/透射率条件恢复被 Gaussian footprint 压掉的细节。作者称模型最多 139k 参数，并在 Mip-NeRF 360 上优于轻量图像超分基线；它已获 MMSP 2026 Best Paper，但本轮没有找到作者代码。

<!-- arxiv:2611.26128 -->

[CryoGaussian](https://arxiv.org/abs/2611.26128)（arXiv:2611.26128）把显式高斯密度直接拟合到冷冻电镜粒子图像，用每图像与每高斯 latent 表示组成和构象差异。作者报告在 CryoBench 达到领先结果，并以专用 additive rasterizer 把训练加速 12.8—28.0 倍；这不是通用场景渲染 benchmark，本轮也没有找到代码。

<!-- arxiv:2611.25523 -->

[MergeableRF](https://arxiv.org/abs/2611.25523)（arXiv:2611.25523）为每个 basis light 训练共享几何、独立外观网络，并用 merge-aware training 让参数线性组合对应目标照明。它同时支持 NeRF 与 3DGS，一次渲染即可得到目标光照，不要求材质估计或逐目标优化；输入仍需要已知 basis lights 的多视图采集，当前没有作者代码。三篇都值得跟踪，但只能称为论文级结果。**判断：P2 论文突破；论文无代码；可信度 A。**

## 相关深读与行动建议

1. **优先跑 Animated SOG 的现成样例，再决定是否接生产资产。** 先在 PlayCanvas WebGPU、WebGL 与 Three.js 三条路径记录首屏时间、峰值内存、循环边界、音画同步和断点下载；再用一段已有 TRiGS 或逐帧 PLY 素材验证编码时间、文件大小、PSNR 和移动端失败模式。
2. **LichtFeld 的模糊筛选只做预选。** 在一个包含运动模糊、景深虚化、低纹理和正常清晰图的项目上统计误选/漏选，再测试 Save As、移动项目目录、换盘符与缺图恢复，确认可移植引用不会静默失效。
3. **VDC Viewer 用真实建筑项目做售前验收。** 准备带坐标基准的 3DGS+BIM，核对格式转换、首屏、平板帧率、厘米级测量误差、权限、外链访问、数据导出/删除和月费之外的存储或流量限制。
4. **PaveSplat 从权重评估开始，不先训练。** 用固定样本直接跑 1×—8× 覆盖与质量指标，确认许可证和第三方权重边界后，再决定是否投入双卡 150k-step 训练。
