## 重点正文

### PlayCanvas Engine v2.24.3 正式移除旧 Apple GPU 上昂贵的浮点 flat 插值

[PlayCanvas Engine v2.24.3](https://github.com/playcanvas/engine/releases/tag/v2.24.3) 于北京时间 11 月 23 日 20:55 发布，纳入 [PR #10112](https://github.com/playcanvas/engine/pull/10112) 和提交 [`3a9f6fa`](https://github.com/playcanvas/engine/commit/3a9f6fa304c302e38746921d81bf9444634db4ac)。修改针对 Gaussian splat 顶点到片元阶段的浮点 varying：原实现使用 `flat` 插值，维护者的跨设备测试显示它在 Apple9 之前的 Apple GPU（包括 M1、M2、A14—A16）会占用 20%—60% GPU 时间，而在其他测试平台最多只带来几个百分点的收益。新版本只保留整数 varying 的 `flat`，浮点值恢复普通插值。

这不是排序、投影或 SOG 格式变化，也不要求重编码 PLY、SPZ 或 SOG 资产；它改变的是渲染 shader 的插值路径。对 Viewer、Editor 发布页和自定义 Engine 集成，最可能的收益是旧 Apple 设备上的帧时和功耗改善。官方数字来自维护者指定场景和设备，本期没有复测，不能泛化成所有 Apple 或所有场景固定提速。

同一 release 还包含多项通用修复，但 11 月 24 日主干后续合入的 WebGPU depth-grab 修复 [PR #10126](https://github.com/playcanvas/engine/pull/10126) 不属于 v2.24.3，不能混写为正式版能力。本轮核对 [SuperSplat](https://github.com/playcanvas/supersplat)、[SuperSplat Viewer](https://github.com/playcanvas/supersplat-viewer) 与 [SplatTransform](https://github.com/playcanvas/splat-transform) 后，未发现比 11 月 23 日稿件更晚的正式版本。**判断：P1 正式性能修复；MIT；建议 Apple 旧设备与 WebGL/WebGPU 双路径马上回归；可信度 A/B。**

### LichtFeld Studio v0.5.4.3 把 VR、碰撞行走和更宽相机模型带入正式版

[LichtFeld Studio v0.5.4.3](https://github.com/MrNeRF/LichtFeld-Studio/releases/tag/v0.5.4.3) 于北京时间 11 月 23 日 18:48 发布。可见交互层新增 OpenXR VR 浏览、手部与抓取、碰撞体和 Walk 模式，加入 gamepad、sequencer、RGB/深度/法线视图以及可选 SteadySplats viewport。扩展层加入 Slang 用户 shader；训练侧把校正后的相机默认打开，可用 `--no-calibration-correction` 关闭，并提供可选 `--pose-opt` 姿态优化，同时把 360° 与鱼眼图像接入快速 rasterizer。

项目 release notes 还报告 7 个场景的单步训练中位数加速约 17%，范围为 13%—22%，并说明显存改为按需增长。这个数字没有附统一 GPU、场景规模和质量终点，本期也没有复现；它更适合用来决定是否做对照测试，而不是直接写进采购容量。SOG 侧是确定性球谐调色板生成，项目文件开始强调跨平台可携带；SAM 2.1、文本选区和批量训练则扩展了编辑与自动化入口。

源码仍是 GPL-3.0-or-later，可自行编译；Windows 预构建包通过项目 portal 提供，费用与账号条件应在采购时单独核对。版本同时包含大量交互面，升级前应复制项目，分别验收相机校正、旧项目读取、训练收敛、SOG 导出、VR 控制器和自定义 shader。**判断：P1 生产工具正式升级；可实际测试，但不宜原地覆盖唯一项目；可信度 A。**

### SpAItial Echo-3 API 开放最多 8 次扫描的服务器端合并

[SpAItial Capture Worlds API](https://docs.spaitial.ai/api/capture-worlds) 现在允许在一个 `zips` 数组中提交最多 8 份扫描。所有扫描必须使用相同输出分辨率和方向；相机姿态要么全部提供，要么全部不提供；相邻扫描需要足够重叠，合并上传总量上限为 8 GiB。官方说明若某份扫描无法与其他扫描形成重叠，系统可能跳过它，但相应帧仍计费。

[官方计费文档](https://docs.spaitial.ai/billing/credits-and-plans) 给出的 Echo-3 API 口径是每次作业 900 credits，加每帧 1 credit；按页面的美元换算，即 9 美元基础费加每帧 0.01 美元。它解决的不是客户端简单拼文件，而是服务器端联合求解和相机姿态细化；输出工作流可继续导出 SPZ、SOG、PLY、mesh、floorplan 与 camera 数据，具体选项仍受套餐和 API 返回能力约束。

这让多房间、跨楼层或分段采集第一次有了明确的公开 API 契约，但“最多 8 份”不等于任意不重叠扫描都能合成。上线前应先用两段小扫描验证重叠阈值、姿态一致性、失败扣费、坐标系和最终 SOG/SPZ 质量，再扩大到完整场景。**判断：P1 商业重建 API；可实际调用；闭源且按 credits 计费；可信度 A。**

### 《狂野时代》把 3DGS 用于虚拟勘景、长镜头预演和 VFX 空间基准

XGRIDS 在 11 月 23 日发布的[官方案例](https://www.xgrids.com/intl/blogs/case-studies/virtual-location-scouting-previs-resurrection)中披露，毕赣电影《狂野时代》的寺庙与码头场景使用 Lixel L2 Pro 采集，并通过 LCC Studio 与 Unreal Engine 插件形成可浏览的 3DGS 场景。官方称团队在 3 天内完成约 50,000 平方米采集，用于远程虚拟勘景、复杂长镜头预演和现场环境与后期 VFX 的共享空间参考。

这个案例的新闻价值不在又一段视觉演示，而在 3DGS 被嵌入美术、摄影、现场执行和后期之间的协作链：不可控的实景地点先转成可反复访问的空间副本，镜头和调度可以在开拍前统一。XGRIDS 还宣称系统达到约 1 cm 相对精度，但文章没有公开独立测量流程、误差分布、资产体量、训练硬件或 UE 帧率，因此不能把这一数字当成通用验收标准。

这是厂商撰写、以合作项目为对象的案例，不是独立第三方评测；软件与硬件也属于商业闭源工具。对影视与大型实景制作团队，它提供了“采集—空间审阅—预演—后期对齐”的可参考组织方式，下一步更值得追问的是坐标交付、版本管理、现场更新和授权成本。**判断：P1 行业应用案例；生产流程已经发生，性能数字需独立验证；可信度 A（事件）/B（效果声明）。**

### LichtFeld for Blender beta 把训练任务放进 Blender 场景

[LichtFeld for Blender v0.1.0-beta.2](https://github.com/MrNeRF/lichtfeld-blender-plugin/releases/tag/v0.1.0-beta.2) 已在 11 月 20 日发布，本期按迟到索引补收。插件通过 LichtFeld 后端从 Blender 5.3 场景生成训练视图，支持 Cycles 与 EEVEE，官方建议使用 4,000—10,000 个相机视角；可选输出 Float32 TIFF 深度与法线监督，并通过 CPU shared memory 在 Blender 中实时预览训练中的 splat。

它把合成场景到高斯资产的路径从“批量渲图—整理相机—外部训练”缩短为可恢复的 job，并提供 portal gallery 导入。当前主要测试平台是 Windows，插件和 Studio 的版本、GPU 后端、场景材质、深度定义与导出坐标仍需一起核对；beta 标记意味着 UI 和文件契约可能继续变化。

仓库采用 GPL-3.0-or-later，代码和 release 可下载，但运行仍依赖 LichtFeld Studio/后端与 Blender 5.3。它适合用一个小型合成场景验证相机覆盖、透明材质、深度监督和实时预览，不适合直接替换现有批处理产线。**判断：P1 beta 创作插件；可实际测试；可信度 A/B。**

### PennyGS 用低于 2 GB 峰值显存训练全分辨率 4K 场景

[PennyGS（arXiv:2611.27525）](https://arxiv.org/abs/2611.27525) 针对 4K 图像训练时的显存峰值和迭代成本，采用分块/采样与训练调度来降低资源占用。论文报告在 RTX 3060 上对 Mip-NeRF 360 以 30,000 次迭代训练约 6 分 25 秒，峰值显存低于 2 GB，并声称在其比较的 10 种方法中至少比最快对手快 3.9 倍。

这些数字必须连同 4K 输入、30,000 次迭代、RTX 3060、数据集和作者选择的质量指标一起理解，不能简化成任意场景“3.9×”。本期没有找到官方训练代码或权重，因而无法核对 CUDA/PyTorch 版本、预处理成本和复现误差。**判断：P1/P2 训练效率论文；论文无代码；可信度 A（论文）/未复现。**

### BladeR 把 45 MP 无人机影像与层次化高斯用于风机叶片检测

[BladeR（arXiv:2611.27407）](https://arxiv.org/abs/2611.27407) 面向风机叶片的高分辨率无人机巡检，把 GPS/IMU、形状先验和层次化场景组织用于相机定位与高斯重建，再在 45 MP 影像和三维空间中定位缺陷。相比一般室内/街景 3DGS，这项工作把高分辨率输入、细长重复结构和工业测量约束放到同一管线。

论文列为 VISAPP 2026 工作，但本期没有找到官方代码、权重或公开数据集，也没有独立工业验收结果。它值得进入能源巡检与摄影测量观察清单，尚不能按可部署检测系统采购。**判断：P2 工业研究；论文无代码；可信度 A。**

<!-- arxiv:2611.27719 -->

### VeilGS 在没有成对正常曝光数据时分解低照度场景

[VeilGS（arXiv:2611.27719）](https://arxiv.org/abs/2611.27719) 试图在只有低照度多视图输入时，将观测拆成反照率、光照与空间变化的 gain veil，再通过全局 tone 映射恢复可查看的三维高斯。关键点是训练不要求同一场景的成对正常曝光数据，因而更接近夜间采集的现实约束。

[项目页](https://errorlogic1211.github.io/VeilGS/) 提供方法说明和视觉结果，但本期没有核实到训练代码、权重与第三方复现。低照度增强很容易把噪声、白平衡和动态范围差异混入“材质”或“光照”，需要等待代码和 RAW/曝光条件后才能判断泛化。**判断：P2 低照度重建论文；论文+项目页、无代码；可信度 A/B。**

<!-- arxiv:2611.27224 -->

### EAST 用事件相机约束 SDF，再由高斯承担可视化表面

[EAST（arXiv:2611.27224）](https://arxiv.org/abs/2611.27224) 把事件相机的高时间分辨率信号用于 SDF（有符号距离场）表面优化，再以 Gaussian 表示提供可微渲染和外观。它瞄准高速运动、运动模糊或普通帧相机曝光不足时的几何恢复，属于事件视觉与 Gaussian surface 的交叉路线。

当前只能核实论文条目，没有找到官方代码、权重、硬件同步配置或独立复现。事件相机型号、对比度阈值、标定、同步和普通帧辅助条件都会显著影响可复现性，因此现在适合跟踪方法，不适合排入短期部署。**判断：P2 事件视觉研究；论文无代码；可信度 A。**

## 相关深读与行动建议

1. **PlayCanvas 先做设备矩阵，而不是盲目全量升级。** 至少覆盖 M1/M2、A14—A16、较新 Apple GPU 和一台非 Apple 设备，在同一 SOG/SPZ/PLY 场景记录 WebGL 与 WebGPU 的 GPU 时间、视觉差异和功耗；不要把主干 WebGPU depth 修复算入 v2.24.3。
2. **LichtFeld 用项目副本做跨功能验收。** 相机校正默认值变化最可能改变旧数据结果；同时检查 360°/鱼眼、SOG 确定性、VR 控制器、碰撞行走、Slang shader 和旧项目可携带性。
3. **Echo-3 合并从两段小扫描开始。** 明确重叠、全部/无姿态、同分辨率和 8 GiB 约束，并把失败扫描仍计费纳入自动化预算和重试策略。
4. **四篇论文都先归档条件，不进入可运行清单。** PennyGS 的 RTX 3060/4K/30k 口径值得优先复现；BladeR、VeilGS 与 EAST 应等待代码、数据与硬件配置。
