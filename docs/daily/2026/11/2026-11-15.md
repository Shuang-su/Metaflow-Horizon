## 速览

今天有三条值得放在一起看，但影响对象不同。NVIDIA 的 ovrtx 0.7.0 首次把 Gaussian splat 的漫反射重照明和实验性 LiDAR 合成放进公开 SDK 发行；Splattic 4.0.0 把 4DGS 剪辑、局部删除、简化、拼接和浏览器发布放进一套公开测试版；Ropedia Xperience 2 则把度量尺度场景、Gaussian splat、网格、相机数据与第一视角任务录像组合成面向 Physical AI 的数据集。前两项仍是预发布或公测，后一项目前可见的是 126 个场景的首批子集，均不能越过公开边界写成成熟生产方案。

工程侧还有两个更窄、但需要立即进入兼容性清单的变化：Niantic SPZ 主干修复了旧版 v1—v3 扩展记录在加载时被静默丢弃；Spirula Studio 主干把大规模可见性掩码改为位打包，并加入可选的低透明度 splat 分裂门槛。它们都没有新 tag，适合锁提交验证，不适合只看 `main` 自动升级。

## 重点正文

### NVIDIA ovrtx 0.7.0 让高斯进入可重照明与传感器仿真管线

NVIDIA 于 11 月 14 日发布 [ovrtx v0.7.0](https://github.com/NVIDIA-Omniverse/ovrtx/releases/tag/v0.7.0)，tag 指向提交 [`d1e4206`](https://github.com/NVIDIA-Omniverse/ovrtx/commit/d1e4206)。这是标为 **Pre-release** 的 SDK 版本，不是稳定版。`ParticleField` Gaussian splat 现在可以使用随包提供的 `ParticleFieldSHDiffuse.mdl` 接收 Path Tracing 或 Real-Time Path Tracing 的光照；随机透明度用于处理大量半透明粒子。官方同时加入实验性的 WPM LiDAR 渲染，可为 NuRec 训练并带 `lidarExtraSignals` 的 Gaussian 生成传感器信号，普通 RGB splat 不会凭空获得 LiDAR 响应。

这解决的是 Gaussian 资产长期只能重放采集光照、难以进入合成照明和传感器仿真的问题，但它不是完整的材质分解。官方说明漫反射反照率由 SH0 推导，采集时的光照仍可能烘焙在颜色里，因此结果更适合可控预览和仿真试验，不能当作真实 intrinsic material。0.7.0 还把 `cameraDistance` 排序改为真实相机距离，阻止 NaN/Inf 位置进入加速结构，并让 Minimal synthetic 模式的 Gaussian segmentation 与实际渲染几何和包围盒一致。

升级边界不小：C/C++/Python 的 handle、token、prim path 类型拆开，结果结构变化，原生消费者需要重编译；`ovstage` headers 不再随包提供，必须自行匹配版本。SDK 包覆盖 Windows x86_64、Linux x86_64 与 aarch64，许可证为 NVIDIA SLA。**判断：P0/P1 平台能力，预发布可实际测试；可信度 A。先在独立分支验证重照明、分割、LiDAR schema 与二进制兼容，再决定是否接入生产。**

### Ropedia Xperience 2 把高斯扫描与 131 小时第一视角任务数据配成一套 Physical AI 语料

[Ropedia Xperience 2（arXiv:2611.17060）](https://arxiv.org/abs/2611.17060) 于 11 月 12 日提交，本期按迟到索引补收。论文描述 1,589 个度量尺度场景扫描，以及 4,230 段、74 类任务、合计 131 小时的第一视角录像。场景被转换为可物理交互的仿真环境，真人动作可重定向为机器人轨迹，并可通过虚拟遥操作和自动化产生长时程训练数据。

当前公开边界比论文总量更重要：[Hugging Face 数据集页](https://huggingface.co/datasets/ropedia-ai/Ropedia-Xperience-2) 标为 CC BY-NC 4.0，现阶段可见首批 126 个场景；[代码仓库](https://github.com/Ropedia/Ropedia-Xperience-2) 提供下载与注册工具。单场景可包含 degree-zero SH 的 `gaussian_splat.ply`、OBJ、COLMAP 稀疏模型、鱼眼图像与遮罩，以及录像对应的运动、位姿和文本描述。不要把论文中的 1,589 个场景写成已经全部在 Hugging Face 可下载。

它的新闻价值在于把“可看”的重建资产与“人在场景中做什么”的行为数据绑定，而不是再增加一个纯新视角合成基准。研究者可以用同一空间坐标系连接视觉定位、具身任务理解、仿真和策略生成；商业使用则会受到非商业数据许可限制。**判断：重要数据基础设施；首批数据与代码可下载，完整规模仍在释放；可信度 A。**

### Splattic 4.0.0 在浏览器里剪辑与发布 4DGS

Splattic 的 [Public Beta 4.0.0 更新记录](https://www.splattic.com/landing/changelog.html) 标注 11 月 10 日发布、11 月 11 日更新，本期是 11 月 15 日迟到发现，不应写成 11 月 14 日刚发布。浏览器编辑器现在可以打开单个 `.4dgs`，与网格和静态 splat 同场使用；播放器支持循环、单次、往返、0.25×—4×、球谐等级和 GPU/CPU evaluation。

编辑能力覆盖 IN/OUT 裁切、变速、反向、盒选/套索/画笔选区，以及整段或时间范围内删除。选区会随 splat 在时间中移动，删除在导出前保持非破坏。工具还能把 PLY/SOG 序列按帧率、对应关系、坐标和时间平滑导入 4DGS，做简化、时间采样、分段和拼接。场景 zip 保存原始资产与编辑列表；HTML 可内嵌较小文件，约 64 MB 以上改用 sidecar；也提供 AR bundle 或 HTTP Range streaming 路径。

这是商业 Web 应用的公开测试版，不应与 Apache-2.0 的 4DGS SDK 混为同一许可，也没有证据表明编辑器自身开源。本轮只核对了公开更新记录，没有在手机或头显上实测发布包，也没有测大文件内存、首帧和 seek 延迟。**判断：P1，公开测试版可直接试用；可信度 A（官方更新记录），设备与规模边界待测试。**

## 简讯

### SPZ 修复旧版扩展记录加载时被静默丢弃

Niantic [SPZ PR #115](https://github.com/nianticlabs/spz/pull/115) 合并为 [`d5abdee`](https://github.com/nianticlabs/spz/commit/d5abdee9b37c426a0b66b961c3d43b5857a24f4f)。旧 gzip SPZ v1—v3 的内存流缓冲没有实现 seek，扩展读取器调用 `tellg()` 得到 `-1`，剩余字节检查会拒绝扩展记录。修复加入 seek 支持，并补上 v2/v3 extension round-trip 测试。

影响范围是旧版文件中的 extension records，不是基础 splat 点数、位置或颜色；当前也只是主干提交，没有新 release tag。依赖旧版扩展元数据的团队应锁该提交读取样本，比较扩展数量与内容，再等待正式发行；不应泛化为“所有 SPZ 文件损坏”。**判断：P1 兼容性修复；Apache-2.0；可信度 B。**

### Spirula 主干压缩大规模可见性掩码，并把低透明度分裂设为可选门槛

Spirula Studio 提交 [`6e4f668`](https://github.com/harry7557558/spirula-studio/commit/6e4f668402a315e819b78fb7f3e542c910c102fb) 把训练中的 visibility mask 改为位打包，并调整 arena/search 内存和 ETA/显存预测。维护者给出的 7500 万 pair 示例中，该掩码从 572.20 MiB 降到 13.42 MiB；完整进程的作者测试则更克制，例如 garden 1/4 30k 从约 500/504 MiB 降到 457/487—504 MiB，1500 万 splat 的 London 场景从 9490 MiB 降到 9364 MiB。前一个数字不能冒充端到端显存下降。

此前提交 [`6caadf0`](https://github.com/harry7557558/spirula-studio/commit/6caadf0c1101bf934a58d5ecd16764ed5c9db057) 增加 `densify_min_split_opacity`：低于门槛的 splat 不再成为分裂源，用于减少 densify 把透明度带走后形成雾化或坍塌。默认值为 0，等于关闭；启用后增长可能达不到目标配额，需要结合 `SS_DENSIFY_STATS_LOG=1` 观察。两项都在主干、没有 tag，且性能数字来自维护者环境。**判断：P1 研究级可测试；GPL-3.0、Vulkan/CUDA；可信度 B。**

### SuperSplat 与 LichtFeld 本窗口没有越过昨日待合并稿的新提交

固定检查的 [SuperSplat](https://github.com/playcanvas/supersplat)、[SuperSplat Viewer](https://github.com/playcanvas/supersplat-viewer)、[SplatTransform](https://github.com/playcanvas/splat-transform)、[PlayCanvas Engine](https://github.com/playcanvas/engine) 与 [LichtFeld Studio](https://github.com/MrNeRF/LichtFeld-Studio) 均已读取近期 commit、合并 PR 与 release。可见的 GSAF 时间线、混合导入、50 条注释、设备恢复阴影、非破坏裁剪、文字选区和 SOG e-means 都属于 11 月 14 日待合并稿，本期不重复。没有把“仓库可打开”误写成所有讨论和 Discord 都已覆盖。
