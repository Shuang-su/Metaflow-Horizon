## 重点正文

### StorySplat 2.6 把 Open4DGS 与 Animated SOG 作为浏览器场景对象播放

[StorySplat 2.6 的发布说明](https://radiancefields.com/storysplat-2-6-plays-open4dgs-and-animated-sog-4d-splats)称，新版可读取 Open4DGS 导出的 `.trigsbin` 时间线和 Arrival.Space 的 `.asog`，要求 `storysplat-viewer` 2.16.0 或更高版本。两条路径都支持 WebGPU 与 WebGL 2，不需要浏览器插件；GPU 每帧计算移动 splat 的位置，因此慢放、循环和时间拖动不需要另取逐帧资产。

这不是单纯的格式列表更新。动态片段可以被场景灯光照明、投射或接收阴影，也能附加热点、测量和触发条件；剪辑器可用方框或球体删除区域、清理低透明度雾点、设置速度关键帧和冻结时刻。`.trigsbin` 的裁剪结果可以烘焙为新文件，`.asog` 还能携带空间化音轨。StorySplat 给出的桌面样例包括：把 343 MB、139 万 splat 的片段裁到 46 万 splat 后生成 113 MB 文件约需 3 秒；一个 40 万 splat、6 秒的 `.asog` 为 12 MB，本地加载约 1.5 秒。这些都是提供方条件下的数字，本期没有独立复现。

边界同样明确：六个 Open4DGS 示例为 319—817 MB、时长 6.7—10 秒；报道估算 `.trigsbin` 每个 splat 约占 152 B 显存，`.asog` 约 72 B。两种格式都不支持流式到达，完整文件下载前看不到片段，手机播放尚未验证。[官方价格页](https://storysplat.com/pricing/)在本期核对时显示 Free 只允许公开、非商业项目；Plus 为 19 美元/月，包含商业使用、私有场景与自托管导出；去品牌和把 viewer 嵌入自有产品需要 Enterprise。**判断：P1 商业 Web 4DGS 工具，researched、未 tested；格式与版本可信度 C/B，价格与许可口径 A。动态高斯发布团队值得用一份 `.trigsbin` 和一份 `.asog` 实测首屏下载、显存、WebGL 2 降级与手机边界。**

### SuperSplat Viewer 重构嵌入契约，让宿主真正拥有页面 UI

[SuperSplat Viewer PR #374](https://github.com/playcanvas/supersplat-viewer/pull/374) 于北京时间 11 月 26 日 02:23 合并，对应提交 [`6b8a3df`](https://github.com/playcanvas/supersplat-viewer/commit/6b8a3dfd047f98c903fee2e937e7833eea03f24f)。它移除 framed viewer 自带的水印，把信息面板改为 `createViewer.onInfo` 回调，让宿主决定内容与样式；全屏也从浏览器页面改为宿主容器，从而避免同页嵌入时错误吞掉整页。`renderViewerHtml` 新增 bootstrap `flags`，快捷键与滚轮行为按宿主控制，短 iframe 不再强制捕获页面滚动。

随后合并的 [PR #371](https://github.com/playcanvas/supersplat-viewer/pull/371) 为 `renderViewerHtml` 增加可转义的 `title`，默认值仍是 `SuperSplat Viewer`；输入不能通过 `</title>` 逃逸。较小的 [PR #373](https://github.com/playcanvas/supersplat-viewer/pull/373) 把 Orbit/Fly 的目标提示改成固定 28 px 的屏幕空间 pinpoint，近景不会显得过大、远景也不会缩没，Walk 仍保留贴地的世界空间圆环，并尊重 `prefers-reduced-motion`。

这些修改影响的是发布与嵌入 API，而不是 SOG/SPZ/PLY 解码或 splat 排序。已有自托管页面最需要回归的是：是否仍依赖内置 info panel、水印、页面级全屏和全局快捷键；只用默认独立页面的用户受影响较小。**判断：P1 主干 API/UX 更新；MIT；可信度 B。尚无对应新 release，生产项目应锁 `6b8a3df` 之后的提交做嵌入回归，不应只升级依赖范围后直接上线。**

### LichtFeld Studio 加入两个 splat 模型的人工点对齐

[LichtFeld Studio PR #4184](https://github.com/MrNeRF/LichtFeld-Studio/pull/4184) 于北京时间 11 月 26 日 00:40 合并，对应提交 [`4859ed2`](https://github.com/MrNeRF/LichtFeld-Studio/commit/4859ed2514ae62b7a32292e97fc36bd5e499af85)。用户选择两个可见 splat 后，在左右独立视图中标注同一物理细节；至少 3 对不共线点才能求解，更多点进入最小二乘拟合。移动模型只允许正的统一尺度、旋转和平移，参考模型保持不动。

预览会显示拟合尺度、RMS 残差和最差点对，并提供分离、左叠加、右叠加和联动相机。应用后只记录一次场景撤销；预览不会改写源 splat，取消可恢复原来的视图。它不做自动对应搜索，也不合并两份高斯数据，因此仍需要人工找到可靠的重叠细节。

维护者报告 Windows Release 构建的 63 个原生测试与 103 个 Python 测试通过，并用约 126 万与 162 万 splat 的 Truck 模型在 RTX 5060 Ti 上走过工作流；但这不是配准精度或性能 benchmark，Linux 和完整 CI 仍未覆盖。项目为 GPL-3.0-or-later，当前变化只在 `master`。**判断：P1 可实际测试的主干编辑能力；可信度 B。多次扫描拼接团队可先用带已知控制点的模型检查尺度、父级变换、残差和撤销，再决定是否替代外部配准工具。**

### SplatTransform 同时补上 CSV 回读和压缩 PLY 的 NaN 隔离

[SplatTransform PR #382](https://github.com/playcanvas/splat-transform/pull/382) 于北京时间 11 月 25 日 20:20 合并，对应提交 [`d10d746`](https://github.com/playcanvas/splat-transform/commit/d10d746202d670fd4c833035390ee68b41d43cdc)。此前 CSV 只能写出，不能再读回；新 reader 让命令行和库 API 都能把数值 CSV 当输入。它按 PLY 坐标空间解释列名，分块读取文本但把每列以 `Float32Array` 常驻内存；标准位置、旋转/尺度/透明度、DC 颜色和球谐余项必须以完整列组出现，部分缺列会显式报错。CSV 没有类型信息，因此大于 `2^24` 的整数和 64 位浮点会损失精度，也不适合大规模随机访问。

[PR #355](https://github.com/playcanvas/splat-transform/pull/355) 于北京时间 11 月 25 日 21:56 合并，对应提交 [`386b3d6`](https://github.com/playcanvas/splat-transform/commit/386b3d6fd878dbab2688e7c7d7164dcbd6e80e34)。原先一个 `NaN` 混入位置、尺度或 DC 颜色，就可能令整个 256-splat chunk 的 min/max 与解码结果变成 `NaN`。修复会跳过或夹紧非有限值，位置无效的 splat 被隐藏；`--filter-nan` 仍可在转换前删除坏行。评审还补了全 `-Infinity` 尺度和混合非有限值的回归测试，避免把 2DGS 式零厚度轴误扩成单位厚度。

两项都是主干提交，并未产生晚于 3.12.0 的正式 tag。**判断：P1 数据互操作与健壮性更新；MIT；可信度 B。CSV 适合调试、表格分析和受控往返，不是新的高效资产格式；经 compressed PLY 生产链处理外部数据的团队应优先用含单个 NaN 与 `-Infinity` 尺度的样本做回归。**

### Spirula 为网格预览和超大点云加上资源边界

Spirula Studio 的 [`28a7bd6`](https://github.com/harry7557558/spirula-studio/commit/28a7bd624e3f297e3a4a42b7703fc850aa7d9391) 重做 meshing GUI，并增加网格生成过程的可视化预览。实现加入独立的 preview budget 与 preview file 路径，按可用设备内存计算预览预算，允许在实际导出前查看表面和参数效果；这降低了“长时间运算后才发现参数不合适”的迭代成本，但不能等同于最终网格已经经过质量或拓扑验证。

随后 [`2a04de6`](https://github.com/harry7557558/spirula-studio/commit/2a04de62ec50a1fd6702d8ca3a9c5d8ae31df309) 把数据集点云预览限制在最多 1,000 万点，以规则步长抽样。提交说明的极端输入达到 5.85 亿点；原方案每点约 24 B GPU 缓冲再加 24 B 主机数据，会填满 16 GB 显卡。限制只影响 GUI 预览，不会静默删减原始数据或训练输入。

同日的 [`77d8d8c`](https://github.com/harry7557558/spirula-studio/commit/77d8d8cefe3b0398e08d6cf0c0df1b85f3d2a085) 允许 SfM 数据集创建结束后直接运行命令：GUI 可测试并保存设置，CLI 使用 `spirula sfm auto --finish-command`。命令直接启动而不经过 shell，`{message}` 作为单个参数替换；成功或失败都会执行，用户取消则跳过。这适合通知和后续流水线，但仍应把命令视为本地可执行权限边界。**判断：P1 主干工作流与资源控制更新；GPL-3.0；CUDA/Vulkan；可信度 B。没有新 release，升级前应分别验证预览抽样、网格预算和结束命令的失败/取消行为。**

### S-Mind 把多视图几何写进语言模型的中间状态，并开放完整复现入口

<!-- arxiv:2611.28649 -->

[S-Mind](https://arxiv.org/abs/2611.28649) 的目标不是先调用外部重建器再让模型读结果，而是在 Qwen3.5 4B/9B 主干中加入一组空间 token：先把多个视图融合成共享三维场景，再在推理切换视角时重新表达同一场景。作者用轻量 readout 从这些 token 解码三维点和相机，观察模型是否真的形成跨视图几何，而不是只提高最终答题分数。

[官方仓库](https://github.com/KANABOON1/S-Mind)已提供 Apache-2.0 代码、4B/9B 的 fusion/SFT/RL checkpoint、SFT 数据和分析 notebook。安装脚本面向 Python 3.12、NVIDIA GPU、PyTorch 2.11、vLLM 0.24 与 CUDA 12.9；作者训练使用 H100 80 GB，几何训练还需要申请 ScanNet 数据访问。评估脚本覆盖 MindCube-Tiny、SPAR-Bench、BLINK Spatial 与 ViewSpatial。

作者报告相对 Qwen3.5 主干最多提升 22.26 个点，4B 模型的跨视图点融合与视角变换 probe 分别达到 65.11% 和 82.17%，同主干下比工具式 agent 快约 100 倍。这些数字没有独立复现，“100 倍”也只在作者所选工具链与生成条件中成立。**编辑摘要：** S-Mind 的新闻价值在于代码、权重、数据和内部几何 probe 同时开放，使“模型内部是否真的有三维场景”成为可复现问题；它仍是 H100 级研究训练栈，不是轻量端侧空间模型。

**判断：P1/P2 空间 AI 研究原型，代码+权重可跑；Apache-2.0，ScanNet 数据另有访问条件；可信度 A/B。优先复现 4B checkpoint 的 probe 和四个 benchmark，再评估是否值得训练或适配自己的多视图任务。**

### Niantic Spatial 把无人机与地面 VPS 融合作为大尺度空间图的下一步

[Niantic Spatial 11 月 25 日文章](https://www.nianticspatial.com/blog/seeing-from-above)讨论把地面手机、360 相机、无人机、卫星影像和矢量地图融合到同一空间模型。文章展示了从消费级无人机图像生成、带地理参照与尺度的 Gaussian splat，并把航拍数据接入 Visual Positioning System（视觉定位系统，VPS）。作者报告在捕获区域内，无人机 VPS 的位姿与方向定位成功率为 85%—90%。

这是一篇厂商研究与产品方向说明，不是新 SDK、定价或可下载模型发布；文章没有给出样本量、误差阈值、场景分布和失败案例，因此不能把成功率外推到一般无人机或自动驾驶地图。**判断：P2 厂商空间 AI 信号；可信度 A（文章与方向）/B（作者性能数字）。值得跟踪地面—空中数据的统一坐标、更新频率与授权边界，暂不构成迁移工具链的理由。**

### PartAgent 与 RoomTokens 展示了两种三维结构推理，但代码尚未释放

<!-- arxiv:2611.32554 -->

[PartAgent](https://arxiv.org/abs/2611.32554) 是免训练的 3D 部件分割 agent：3D 专家提供结构区域，2D 多视图专家补语义证据，闭环再选择检查、修复、组合或重选动作。作者报告 PartObjaverse-Tiny-WT 上 68.41 mIoU、领先最强对手 8.53 点，另外四个数据集平均 69.36、领先 7.28 点。[项目仓库](https://github.com/yangcaoai/PartAgent_Agent_for_3D_Part_Seg)目前明确写着代码尚未发布，因此只能查看论文、项目页与演示，不能标为可运行项目。

<!-- arxiv:2611.30219 -->

[RoomTokens](https://arxiv.org/abs/2611.30219) 用分层离散网格 token 同时保存语义类别、实例颜色身份和朝向场，再用 masked diffusion 生成受楼层平面约束的室内布局。它强调显式占用与方向结构，针对的是室内场景合成，不是 Gaussian viewer 或扫描器。[官方仓库](https://github.com/3dlg-hcvc/RoomToken)采用 MIT，但 README 仍只有项目与论文链接，并标注“Code is coming soon”。

**编辑摘要：** 两项都把“结构”从最终几何提前到可检查的中间表示：PartAgent 面向现有物体的部件划分，RoomTokens 面向新场景布局生成；现在都不能下载完整实现，作者指标也未独立复现。**判断：P2 论文+演示/占位仓库；可信度 A/B。**

## 相关深读与行动建议

1. **Web 4DGS 团队先做两格式门槛测试。** 使用时长和 splat 数接近的 `.trigsbin` 与 `.asog`，记录文件大小、完整下载时间、首帧、峰值显存、WebGPU/WebGL 2 帧率、手机失败方式与剪辑后体积；不要拿本地桌面加载数字当公网指标。
2. **自托管 SuperSplat Viewer 的项目测试宿主契约。** 锁定 PR #374 之后的提交，回归 info callback、容器全屏、页面滚动、快捷键、iframe 高度和旧自定义 CSS；稳定 tag 出现前保留现网版本。
3. **扫描拼接团队试 LichtFeld 点对齐。** 用带真实控制点的双模型比较 3 对与多对点的残差、尺度、父级变换和撤销，再与 ICP 或外部配准结果对照。
4. **数据转换链构造坏值样本。** 用单个 `NaN`、全 `-Infinity` 尺度、缺失 CSV 列组和超大数值验证 SplatTransform；确认错误是被隔离或显式拒绝，而不是静默改坏其余 splat。
5. **空间 AI 先复现 S-Mind 4B 推理。** 下载现成 checkpoint 跑四项 benchmark 与 probe，测实际显存、吞吐和多视图失败样例；作者的 H100 训练配置不应被当成最低推理配置。
