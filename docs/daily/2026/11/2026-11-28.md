## 重点正文

### Octane 2027.1 把 glTF 高斯导入与更快光栅正式带进 DCC 渲染链

[OTOY 官方发布页](https://home.otoy.com/render/octane-render./news/octane2027/)确认 Octane 2027.1 于 11 月 26 日公开发布，本期在 11 月 27 日媒体索引出现后补收。新版本的初始 glTF 2.0 导入能够读取 `KHR_gaussian_splatting`，Gaussian splat 节点增加 transform 与 color space pins；新的实时神经渲染视口也明确包含 Gaussian splats，但只在受支持 GPU 上启用。对已有 Octane/DCC 管线而言，实际变化是高斯可以随 glTF 资产进入同一渲染器，并在节点层处理坐标和颜色，而不必只停留在独立 Web viewer。

性能数据必须保留条件。OTOY 的实验室汇总是 Windows/Linux 吞吐 1.2—2.5 倍、macOS 1.9—3.8 倍；公开示例使用约 300 万个 splat、512 samples per pixel 和 RTX 5080，同一场景从 Octane 2026.6 的 11.7 秒降到 2027.1 的 4.8 秒，即 2.5 倍。官方没有在同一页公布所有测试场景、完整 GPU 表、显存占用或画质指标，因此本期没有把“最高 3.8 倍”改写成普遍承诺。

OTOY 同页还预告 Octane 2028 的“8D relightable splat”，但它处于 closed beta / roadmap，不是 2027.1 已交付功能。Octane 是付费商业软件；本期 researched、未安装或渲染。**判断：P0/P1 正式商业发行，可信度 A。现有 Octane 团队值得立刻用自有 glTF 高斯测试导入方向、颜色空间、动画/变换、采样噪声、显存和 DCC 插件版本；没有 Octane 授权的团队不应仅为一个峰值倍数贸然迁移。**

### Spirula 正式版同时解决遮罩语义、AMD RDNA 4 与训练交付

[Spirula Studio v2026.11.27](https://github.com/harry7557558/spirula-studio/releases/tag/v2026.11.27)于北京时间 11 月 27 日 14:41 发布，提供 Windows Vulkan、Ubuntu Vulkan 与 macOS arm64 Vulkan 安装资产，代码采用 GPL-3.0。发行说明确认：改善通用网格质量和低纹理表面训练，优化训练显存与预测，加入 RDNA 4 训练加速、训练时间/显存分解提示、网格实时预览、Voronoi 分区、3DGUT tiling 修复、正交相机、天空盒、DJI Osmo 360 II telemetry、训练图像分辨率上限和大规模 SfM 的 32 位索引修复。

三类 `segment_and_ignore` 遮罩是最值得理解的新语义。[PR #384](https://github.com/harry7557558/spirula-studio/pull/384)规定灰度 0—127 为 Ignore，不参与 RGB、感知、几何、正则和评估；128—250 为 Segment，不参与颜色/几何损失，但会被监督为空；251—255 才按普通静态场景训练。这允许同一张外部遮罩同时表达“移动物体不要学”和“天空等区域应趋向透明”。内置分割工具仍只生成二值遮罩，三类遮罩需要外部准备，不能把它理解为自动分割已经完成。

RDNA 4 优化来自作者主导的 Vulkan 原子操作与 kernel 改造。[PR #390](https://github.com/harry7557558/spirula-studio/pull/390)在 Radeon AI PRO R9700、Mip-NeRF 360 garden、`images_4`、30k steps 的单次作者测试中报告 37%—39% 墙钟时间下降，但只实测 Navi 48 的一个型号；后续 [PR #424](https://github.com/harry7557558/spirula-studio/pull/424)又在多场景 2—3 次测试中报告额外约 5.3%—7.7% 改善。两组数据口径不同，不能相乘，也不能外推到所有 RDNA 4 卡。正式版还可直接保存 SuperSplat 兼容的 Y-up PLY，降低训练到 Web 编辑的坐标转换摩擦。

**判断：P1 正式开源发行，可实际测试；GPL-3.0；可信度 A/B。优先用户是 AMD RDNA 4、复杂遮罩、大数据 SfM 和训练后进入 SuperSplat 的团队。升级前保留旧版输出，用同一数据比较低纹理表面、遮罩边界、网格、显存预测和 Y-up 朝向；发行说明也明确承认训练与网格质量会有预期差异，应把回归检查当作升级步骤。**

### SuperSplat 主干重做选择轮廓、标记透明度与拖动刷新

[SuperSplat PR #1122](https://github.com/playcanvas/supersplat/pull/1122)恢复 selection color 的 alpha 作为高斯选择 tint 强度，对应合并提交 [`f5e65e5`](https://github.com/playcanvas/supersplat/commit/f5e65e5ecb2a75649aed9ec4305bae33ef4590ff)。[PR #1124](https://github.com/playcanvas/supersplat/pull/1124)让未选择中心与圆环按颜色 alpha 淡出；为了避免数百万半透明中心造成 blend contention，低于 alpha 1 时先做深度预通道，再只给每个像素最前方中心着色。维护者在 440 万 splat 的 `church.ply` 上测得多次混合像素从 1.8% 降到 0.003%，但半透明中心仍把 GPU 时间从约 10.0—10.2 ms 提高到 13.7—14.4 ms。该 PR 还把 x-ray-off 的 ID pass 推迟到拖动释放并相机停稳后，避免暂停拖动时反复刷新。

[PR #1126](https://github.com/playcanvas/supersplat/pull/1126)进一步让 outline 取代已选中心/圆环标记，避免两者叠加遮住轮廓；picker 仍保留 marker，因为圆环决定可点击范围。rings 模式重新描整个 footprint，centers 模式只描 core；隐藏的已选 splat 不再留下轮廓，地面网格也不会被 outline 追踪。stochastic frame 不画 outline 时仍保留选择标记，说明它没有用轮廓换掉随机渲染交互反馈。

这些变化直接影响 Editor 的 selection/picking、颜色预览、x-ray 和交互 GPU 成本，不涉及 SOG/SPZ/PLY 解码、LOD、streaming、viewer export 或发布 API。三个 PR 已在 11 月 27 日合并，最新合并提交是 [`70bbed7`](https://github.com/playcanvas/supersplat/commit/70bbed773cc8fb52753dc1f602f9254905a52d6a)，但没有新的 SuperSplat 正式 tag。**判断：P1 主干编辑体验更新；MIT；可信度 B。大量 splat 编辑、半透明 marker 与 outline 用户值得锁 SHA 测试；生产环境应等待包含这些提交的 release，并分别测 alpha 1 与 alpha < 1 的成本。**

### LichtFeld 修复恢复训练的深度锚点，并补上 Apple Vulkan 的 MRNF 逻辑

[LichtFeld Studio PR #4219](https://github.com/MrNeRF/LichtFeld-Studio/pull/4219)修复 depth-anchor sidecar 在恢复 checkpoint 时被错误判失效的问题。旧指纹依赖恢复后的 Gaussian 位置，可能触发重新拟合并改变深度监督目标；新实现把锚点几何指纹写进 checkpoint，在相机和深度输入没变时复用 sidecar，cache miss 时再尝试恢复源点云。PR 所述 16,608 图像数据集原拟合约 33 分钟，但该真实数据集和 GUI 没有在本次修复验证中重跑，验证主要使用 WSL2、CUDA 12.8 与合成 COLMAP fixture。

[PR #4213](https://github.com/MrNeRF/LichtFeld-Studio/pull/4213)只移动了 Vulkan MRNF shader 中 blend peak 的清零顺序，却修复了重要的 Apple Silicon/MoltenVK 行为：原顺序会让清零后的 0 被读回，导致 render count 永远不增加，retire quota 与 keep-covered 失效。Apple M3 Ultra 的测试显示修复后 7,000-step garden 运行实际退休 84,979 个 splat，而旧版为 0；RTX 5090 的 Vulkan 路径原本不受影响。画质数字接近，但这仍是作者的一次运行，不是完整 benchmark。

同日 [PR #4224](https://github.com/MrNeRF/LichtFeld-Studio/pull/4224)给 Align Models 预览加入 wipe 对比：参考模型在左、对齐后的移动模型在右，共用相机并可拖动分隔线。三个 PR 都已合并，合并提交分别为 [`3d5293f`](https://github.com/MrNeRF/LichtFeld-Studio/commit/3d5293f84b05472f19d778fdcc1e2684b3efbdcf)、[`337f6c8`](https://github.com/MrNeRF/LichtFeld-Studio/commit/337f6c8ea189367e4824a6f04114f293e227c76f)与 [`7953aea`](https://github.com/MrNeRF/LichtFeld-Studio/commit/7953aead970ed4a3a833283dce6bff5b6f302cfb)，尚无对应新 release。**判断：P1 主干训练正确性与编辑更新；GPL-3.0-or-later；可信度 B。恢复深度监督和 Apple Vulkan MRNF 的用户应优先回归，其余平台不必因标题盲目升级。**

## 相关深读与行动建议

1. **Octane 用户先验证互操作，再追峰值倍数。** 用一份已知方向和颜色空间的 `KHR_gaussian_splatting` GLB，记录 Octane 2026.6/2027.1 的导入、transform、颜色、512 spp 时间、显存和噪声；同时核对目标 DCC 插件是否已配套。
2. **Spirula 正式版适合做一次带回滚点的升级。** 优先准备三类遮罩、低纹理墙面、大规模 SfM、Y-up PLY 与 RDNA 4 夹具；记录驱动、GPU、分辨率、preset、步数和画质，不把 R9700 的作者数据套到别的卡。
3. **SuperSplat 测试要把交互成本拆开。** 比较 alpha 1 与 0.3、中心与圆环、outline、stochastic movement、x-ray drag release 和 picker；确认视觉更清楚的同时，没有把大场景操作拖到不可用。
4. **LichtFeld 先做恢复一致性。** 在同一 checkpoint 上比较 depth sidecar 是否复用、监督目标是否变化；Apple Silicon 用户再单独观察 MRNF retired/exchanged/pruned 计数。Align Models 的 wipe 则用有遮挡的两模型检查相机和分隔线一致性。
5. **商业平台先索取退出与格式边界。** Arrival.Space、TAS Visuals 和 4DV.ai 分别涉及云空间、现场演出和 4D 资产；在采购或报名之前核对数据区域、导出、格式、版本、资产许可与长期可访问性。
