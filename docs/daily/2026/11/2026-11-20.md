## 速览

今天最值得关注的是 SOG 制作链从“固定压缩参数”向“给定颜色误差目标”迈了一步。[SplatTransform 3.12.0](https://github.com/playcanvas/splat-transform/commit/5d5be2bca17f634f7e706d9fa63a47f2e0112520) 会为每个 LOD 单元选择满足误差目标的最小球谐调色板，不再统一使用固定大小。作者在 30 个场景上报告，默认误差目标 5 的总体代价是编码时间约增加 12%、文件约增加 9%；但复杂场景的 SH 质量可以明显提高，简单场景则可能更小。这个变化不是“所有文件都更小”，而是把质量—体积折衷变成可明确控制的参数。

同一条 PlayCanvas 工具链还解决了两个日常制作问题。[SuperSplat 3.9.1](https://github.com/playcanvas/supersplat/commit/292f53b8f6924a5533d993c0fa1ce078be91f042) 会对至少 100 万个 splat 的场景自动生成 LOD，并按场景本身的 SH 阶数发布；[3.9.2](https://github.com/playcanvas/supersplat/commit/7912e1d518f04326ca7f2c674b5af9b72a5409ab) 为失联的导出目录加入 2 秒超时，避免浏览器一直卡在读取旧目录权限。前者改变发布默认值，后者修复稳定性，升级前都值得用现有项目做一次回归。

大型 DCC 也开始把动态高斯当作时间线资产。[3ds Max 2027.3](https://help.autodesk.com/view/3DSMAX/2027/ENU/?guid=GUID-6B92C7C0-714E-4823-BF73-41EAAEB2F921) 的 Editable Point 对象可以从磁盘载入 PLY/SPZ 静态资产或 PLY 序列；序列会随 Max 时间线更新，官方把这条路径明确写成 4DGS 序列支持。它仍主要是查看、变换与数据管理入口，不代表 3ds Max 已经内置 4DGS 训练或跨格式动态导出。

研究与开源主干也有三条可行动信号：Facet‑SLAM 公开了三角形 splatting 的 RGB‑D SLAM 代码；LichtFeld 大幅降低深度/法线先验缓存占用并默认开启相机标定校正；Spirula 则继续修正 2DGS/3DGS 到网格的融合、补洞与折叠面处理。这些都需要锁具体提交测试，不能当作已经验收的正式版功能。

## 重点正文

### SplatTransform 3.12.0 用颜色误差目标选择 SOG 的 SH 调色板

[SplatTransform PR #383](https://github.com/playcanvas/splat-transform/pull/383) 对 SOG（PlayCanvas 的流式、分层高斯格式）球谐系数压缩方式做了结构性调整。过去每个 LOD 单元使用预设大小的 SH 调色板；现在编码器会在 GPU 上运行 e-means，并选择能满足 `--sh-color-error` 目标的最小调色板。默认目标为 5；SOG v3 的上限是 262,144 色，v2 是 65,536 色。没有可用 GPU、或 SH 数据超过约 2 GB 时，会回退到固定调色板路径。

这不是无条件压缩突破，而是更可预测的质量控制。作者给出的 30 场景汇总中，默认目标 5 相对 3.11.2 平均编码时间增加约 12%，文件增加约 9%；目标 6 才接近旧版总体时间和体积。场景差异很大：细节丰富的场景可能增加体积但把 SH PSNR 提高 3.4—13.5 dB，简单场景则可能减小文件并损失最多约 6.2 dB。Church 的 440 万 splat 样例从 168 MB 降到 153 MB，SH PSNR 从 40.6 提到 42.8 dB；Parish 的 3490 万 splat 样例则从 1145 MB 增到 1183 MB，PSNR 从 40.9 提到 45.2 dB。以上都属于作者基准，且新的调色板步骤峰值显存约为旧路径两倍。

工程影响在于，团队可以把 SOG 质量预算写进构建参数，并让不同 LOD 单元独立分配调色板，而不是为最复杂区域统一抬高全场成本。升级时应固定同一 PLY/SOG 输入，分别跑目标 4、5、6，记录编码时间、峰值显存、总字节数、各 LOD 的视觉差异和 Web 端解码；若构建机没有 GPU或单场 SH 超过回退门槛，结果不会走新算法。项目为 MIT，要求 Node.js 22 或更新版本；3.12.0 已写入包版本并有对应提交，但 GitHub Releases 页面不是这次发布的权威记录。**判断：P0/P1 压缩构建链升级；可实际测试；可信度 B。**

### SuperSplat 3.9.1/3.9.2 修改大场景发布默认值并修复导出目录卡死

[SuperSplat PR #1114](https://github.com/playcanvas/supersplat/pull/1114) 进入 3.9.1 后，发布和导出对 100 万个及以上 splat 的场景自动启用 LOD，不再显示“Generate LODs”开关；SH Bands 滑块也被移除，导出的 SOG 使用源场景自身的球谐阶数。此前用户若为了提升编辑器预览速度临时降低 SH 阶数，可能在不知情时把较低阶数带进发布文件。新逻辑把查看设置与资产内容分离，减少不可逆的发布质量损失。

[PR #1115](https://github.com/playcanvas/supersplat/pull/1115) 进入 3.9.2 后，为 IndexedDB 中保存的导出目录句柄增加 2 秒超时。如果网络共享、USB 盘或已删除目录无法响应，导出窗口会继续打开并要求重新选择目录，而不是无限等待；保存的旧句柄会在下一次启动时重试。维护者已做浏览器路径测试，但 PR 明确没有在真实失联 Windows 共享盘和 USB 设备上覆盖所有组合。

对 Editor/Viewer/SplatTransform 的实际影响可以分开看：Viewer 本窗口没有新版本，SOG 解码协议也没有变化；Editor 的大场景发布默认行为和 SH 来源发生了变化，SplatTransform 则在相近时间升级了编码质量控制。生产团队应把 3.9.0、3.9.1、3.9.2 导出的同一大场景做文件大小、SH 阶数、LOD 层级与首屏时间对比，并故意断开一次旧导出目录验证超时恢复。**判断：P1 编辑与发布工具更新；MIT；可马上回归测试；可信度 B。**

### 3ds Max 2027.3 把 PLY 序列作为 4DGS 资产接入时间线

[Autodesk 3ds Max 2027.3 更新说明](https://help.autodesk.com/view/3DSMAX/2027/ENU/?guid=GUID-6B92C7C0-714E-4823-BF73-41EAAEB2F921)新增 Gaussian splat 的视口显示，并加强从磁盘读取高斯资产。[Editable Point 文档](https://help.autodesk.com/view/3DSMAX/2027/ENU/?guid=GUID-2EE47C36-BBA0-4DD5-85C4-8AA73B146613)把数据源分为 Static 与 Sequence：静态对象可载入 PLY 或 SPZ，序列使用按帧编号的 PLY 文件，并会随着 3ds Max 时间线自动更新。预设中还列出 Generic、Postshot、Substance 与 World Labs，用于匹配不同属性布局。

这一入口的意义是让 4DGS 不必先烘焙成视频或自定义插件面板，就能与相机、灯光和 DCC 时间线一起检查。它适合镜头布局、合成前检查和资产管理，但公开文档没有声称 3ds Max 能训练动态高斯，也没有把序列打包成单一标准容器。SPZ 出现在静态输入路径，官方对动态序列描述的是 PLY；不能把两者混写为“SPZ 4DGS”。

项目落地前应核对实际文件命名、帧率映射、属性预设、缺帧处理、内存增长和时间线拖动性能，再确认 PLY 导入/导出的属性是否能保留训练器所需数据。**判断：P0/P1 商业 DCC 原生工作流扩展；正式版本文档；可信度 A。**

### LichtFeld 主干压低先验缓存，并把标定校正改为默认开启

[LichtFeld PR #4133](https://github.com/MrNeRF/LichtFeld-Studio/pull/4133)不再把深度和法线先验提前放大到原图尺寸，而是保持自身分辨率直到损失函数读取；RAM 缓存同时改用无损 JPEG 2000。作者在 1557 张照片、5220×3902 像素、半分辨率先验的测试中，系统内存峰值从约 186/191 GiB 降到 76.6 GiB，显存从约 12 GiB 降到 6.7 GiB；首轮训练速度从 5.4/9.0 提到 24.1 steps/s。另一组 168 张约 30K 图像测试中，RAM 从 37.9 GiB 降到 20 GiB，先验缓存从 23.9 GiB 降到 5.9 GiB，显存从约 27.8 GiB 降到 23.3 GiB。以上是作者在 Windows 11、RTX 5090 与大内存工作站上的结果，不能直接外推到普通机器。

[PR #4147](https://github.com/MrNeRF/LichtFeld-Studio/pull/4147)将相机标定校正改为新项目默认开启，作者的 7 场景公开基准中平均对齐 PSNR 从 27.93 提到 28.27 dB，训练成本增加约 3%—4%；但普通室内 held-out 视图也出现最多 0.74 dB 的下降。旧项目如果没有配置键会保持关闭，用户可用 `--no-calibration-correction` 明确禁用。[PR #4154](https://github.com/MrNeRF/LichtFeld-Studio/pull/4154)还补上 12 处 CUDA stream 排序边，主要保护非阻塞 stream 下的 SH 重排、增长、gather 和导出；维护者没有指出当前应用中已知触发路径。

这批变化都在 GPL-3.0 主干，没有新正式 tag。最合理的验证方式是用一个有深度/法线先验的中型场景测 RAM、显存、首轮与稳定阶段吞吐，再用相同 split 对比标定校正开关；不要只采用平均 PSNR，也要看室内近景退化。**判断：P1 训练资源与标定工程更新；锁提交可测试；可信度 B。**

### Facet‑SLAM 公开实时三角形 splatting 的 RGB‑D SLAM 代码

<!-- arxiv:2611.23935 -->

[Facet‑SLAM](https://arxiv.org/abs/2611.23935)（arXiv:2611.23935）不用高斯椭球，而是以可微分三角形 facet 表示场景，并把增量 Delaunay 网格、跟踪和渲染放进 RGB‑D SLAM。论文作者报告桌面 GPU 约 100 fps、Jetson AGX Orin 可跟上传感器帧率；在 Replica 上，Delaunay 网格 Chamfer distance 从一个光度优化基线的 1.55 cm 降到 0.86 cm，同时速度高于该基线 20 倍以上。数字来自论文作者，硬件、场景与对照口径必须随引用保留。

[代码仓库](https://github.com/edward62740/Facet-SLAM)已经包含安装脚本与 TUM、Replica、ScanNet、RealSense D435 路径，但仍是最小研究发布。依赖包含 Eigen3、PCL、PyTorch、CUDA 扩展、Ceres 2.2 和 CUDA 12.x；README 估计会下载约 2 GB 的 PyTorch 组件并编译五个扩展，完整 v1.0 路线仍未结束。许可说明以研究、非商业使用为主，企业或产品集成不能只看仓库可下载就推定可商用。

它值得关注的原因不是替代所有 3DGS SLAM，而是三角形表示天然提供可编辑、可测量的表面拓扑，可能减少从辐射场再转网格的后处理。首轮复现应使用官方 Replica 配置，记录跟踪丢失、网格完整度、帧率、峰值显存和导出结果，再决定是否接 RealSense。**判断：P1/P2 有代码研究原型；可实际复现但非生产可用；可信度 A/B。**

### Spirula 继续修补 2DGS/3DGS 到网格的融合与拓扑清理

[Spirula 提交 `ac15615`](https://github.com/harry7557558/spirula-studio/commit/ac156157dd8c4216e440b88ec265b7bdaf63a4e5)改进场融合、patch 剔除、补洞、交叉与折叠面修复，并加入更自适应的 TSDF 处理。作者在 dessert 数据上报告：2DGS 网格 F-score 从 0.738 提到 0.770，meshing preset 从 0.749 到 0.770，2DGS 的 TSDF 路径从 0.658 到 0.805；同一更新里 3DGS 从 0.813 略降到 0.800，说明它仍是按表示和数据集权衡的工程改动，而不是全面提升。

这个提交发生在 11 月 20 日 00:33（北京时间），是 GPL-3.0 主干变化，没有正式 release。11 月 19 日稿件已经记录的 2DGS、TSDF、OpenGL 栅格器与 Voronoi 分区不再重复写成今日新品；本期只记录后续网格质量修补。验证时应把 2DGS、2DGS preset 与 3DGS 分开，并同时看 precision、recall、F-score、孔洞、floaters、时间、RAM 和显存。**判断：P1 主干网格更新；可信度 B。**

### 两篇论文分别处理动态流式锚点与原子级结构重建

<!-- arxiv:2611.23416 -->

[OCLDA‑GS](https://arxiv.org/abs/2611.23416)（arXiv:2611.23416）用对象中心锚点和分层流式策略管理动态高斯。作者报告在 N3DV、Meeting Room 与 Google Immersive 上相对 IGS 分别提高 0.169、0.202、0.199 dB，并把平均 refinement drop 降低 9.2%—13.8%；当前没有找到官方代码，属于论文无代码，微小 PSNR 差异不能脱离数据集和码率解释。

<!-- arxiv:2611.23444 -->

[Gaussian Splatoms](https://arxiv.org/abs/2611.23444)（arXiv:2611.23444）把各向异性高斯扩展到原子中心的元素类型、占据与热参数，用于三维原子结构重建。[作者仓库](https://github.com/nalinimsingh/gaussian-splatoms)已有训练与数据流程，但 README 仍保留较早标题和 2025 ICCP 表述，说明论文版本与代码说明尚未完全同步。它是科学成像中的专用表示，不应直接外推到通用场景重建。**判断：P2 研究论文；前者无代码、后者有研究代码；可信度 A/B。**

## 相关深读与行动建议

1. **先把 SOG 质量目标纳入构建矩阵。** 对一处纹理简单和一处高频细节场景分别跑 `--sh-color-error 4/5/6`，记录每个 LOD 的 palette 大小、编码时间、峰值显存、总字节数和 Web 端效果；同时确认是否触发无 GPU/大数据回退。
2. **SuperSplat 升级要验证“发布”而不只是“打开”。** 使用超过 100 万 splat、带多阶 SH 的现有项目，对比 3.9.0 与 3.9.2 的 LOD、SH、SOG 大小和 Viewer 首屏；再断开网络盘或 USB 盘验证 2 秒超时后的恢复路径。
3. **3ds Max 的 4DGS 先做短序列互操作。** 准备 20—30 帧 PLY 序列，核对命名、时间线帧率、缺帧、属性 preset、内存与 PLY 导出。SPZ 只按官方文档的静态路径测试，不把它当成动态序列容器。
4. **LichtFeld 和 Spirula 都要使用表示专属基准。** LichtFeld 分别比较先验缓存与标定校正开关；Spirula 分开评估 2DGS、2DGS preset 和 3DGS 网格，避免用一个平均数字掩盖 3DGS 的回退。
5. **Facet‑SLAM 从官方 Replica 配置开始。** 先确认 CUDA 12.x 扩展、Ceres 与 PCL 能稳定编译，再测桌面 GPU 与 Jetson；许可没有明确放宽前，不进入商业产品依赖树。
