## 重点正文

### PlayCanvas 修复修改器旋转下的高斯方向翻转

[PlayCanvas Engine PR #10025](https://github.com/playcanvas/engine/pull/10025) 于北京时间 11 月 16 日 02:21 合并，对应提交为 [`ebc152e`](https://github.com/playcanvas/engine/commit/ebc152e01d4dd2227e5075f7898623a6a8d29e7d)。问题只出现在 packed 工作缓冲：缓冲区保存四元数的 `x/y/z`，读取时用正平方根重建 `w`。拷贝阶段原本会先把 `w` 规范为非负，但 `modifySplatRotationScale` 随后合成的旋转仍可能得到负 `w`；写回时若只保留 `x/y/z`，下一阶段强制重建正 `w`，就会得到错误方向。维护者描述的可见症状是，大角度旋转后细长高斯从表面异常伸出。

修复在修改器执行后再次统一四元数符号，并同时落到 WGSL 与 GLSL 的 packed writer。没有使用旋转修改器的静态 splat 不在主要影响范围；会改变旋转的动画、骨骼蒙皮或节点修改路径才需要优先验证。工程上应准备一个非对称、细长 splat 夹具，在 WebGPU 与 WebGL 2 中对比大于 90° 的连续旋转、骨骼插值和相机切换，而不是只看静态截图。

这是已合并主干修复，不是已发布 npm 版本。若项目当前依赖正式发行，应等待包含该提交的 tag；若缺陷已阻塞交付，可以锁 [`ebc152e`](https://github.com/playcanvas/engine/commit/ebc152e01d4dd2227e5075f7898623a6a8d29e7d) 验证。**判断：P1 运行时正确性修复；MIT；主干可测试；可信度 B。**

### Budget3D 开放一套按内容分配计算预算的图生高斯管线

[Budget3D](https://github.com/BudgetAny/Budget3D) 是 BudgetAny 团队对 BudgetPix 计算自适应 token 思路的非官方开源扩展。它把空间变化低、内容空白的潜变量区域优先合并，把更多 token 留给轮廓和细节，再接入 Idol / Idol-Turbo 生成 `.ply` Gaussian splat。仓库在 11 月 15 日的提交 [`95bbeab`](https://github.com/BudgetAny/Budget3D/commit/95bbeab46063375d560f9b20fa7b9d9fedb078f7) 固定了上游 Idol SDK 版本、补齐 `plyfile` 依赖，并加入[在线演示](https://huggingface.co/spaces/BudgetAny/Budget3D)和社区 WebUI 链接。

现在可下载的内容包括代码、[Budget3D-Idol](https://huggingface.co/BudgetAny/Budget3D-Idol)与[Budget3D-Idol-Turbo](https://huggingface.co/BudgetAny/Budget3D-Idol-Turbo)权重。代码为 MIT，Budget3D 权重标为 Apache-2.0；DINOv3、FLUX.2 VAE 与 Idol 上游仍有各自许可和访问条件。公开安装说明要求 Python 3.11—3.13（作者测试 3.12）和 CUDA GPU，输出可以直接进入现有 PLY 查看器。

它的价值是用一个权重覆盖不同计算预算，而不是为每个预算训练独立模型；但仓库明确写着技术报告“即将发布”，目前没有足够材料核对速度、显存、质量指标和不同预算的对照条件，也不能把项目名理解为 BudgetPix 官方发行。**判断：P1 研究原型，代码+权重+在线演示可测试；可信度 B。先用同一批输入记录 token 预算、墙钟时间、显存、splat 数和几何破损，再谈效率收益。**

### Spirula 主干把大图输入、点云编辑和 GPU 卡死恢复放进同一轮工程更新

Spirula Studio 提交 [`84e296f`](https://github.com/harry7557558/spirula-studio/commit/84e296f3933b9e43e05039c38399143768b469b8) 新增 `--max-resolution`，按长边给输入图、评估相机和网格相机设置绝对上限。它会先执行原有整数缩放，再按实际尺寸限边；较小图像不会被放大，相机内参跟随实际输出尺寸更新。与只用 `--resolution` 的整数倍率相比，这让混合分辨率素材更容易控制峰值显存和训练时间。

提交 [`5336f4b`](https://github.com/harry7557558/spirula-studio/commit/5336f4ba6ad5a3e604447a344c1b8f3c3103dc1f) 让编辑后的稀疏或稠密点云副本出现在“Starting points”列表，并把当前选择直接带进训练器，不再强制回到默认 dense seed。提交 [`8949092`](https://github.com/harry7557558/spirula-studio/commit/8949092edb41bd60fede5a8cb71a7817e2d924e0) 则处理 Vulkan GPU timeout 后驱动销毁阶段永久等待的问题：无进展达到门槛后进程直接 `_Exit`，避免 CLI 或批处理一直挂起。

直接退出提高了无人值守任务的可恢复性，却不是优雅恢复，未保存状态可能丢失；图像限边也会改变有效内参和可见细节，不能只比较训练速度。当前正式 release 仍是 [v2026.11.12](https://github.com/harry7557558/spirula-studio/releases/tag/v2026.11.12)，上述变化都仅在主干。**判断：P1 工程改进；GPL-3.0、Vulkan/CUDA；锁提交可测试；可信度 B。**

### Splat Fashion 把三套真实服装扫描做成浏览器换装作品

[Splat Fashion](https://github.com/willeastcott/splat-fashion) 于 11 月 12 日公开，本期按 7 日重查补收。作品把同一人物的三套真实服装 Gaussian 扫描放进浏览器，用 9 个刚性骨骼驱动 splat，并在没有逐点对应关系的捕获之间做形态过渡。球谐颜色被整理成 65,536 项共享调色板；作者称三套标准细节资产合计约 47 MB，并提供 WebGPU 优先、WebGL 2 回退和手机轻量模式。

作者在 README 报告 iPhone 14 Pro 标准细节 WebGPU 约 48 fps、全 SH 包约 21 fps，WebGL 2 全包约 10 fps；这些是作者环境数据，本期没有复测。代码为 MIT，捕获资产为 CC BY 4.0，页面中的品牌和价格为虚构内容。它最值得借鉴的是“多次独立捕获如何共享 rig、标签和调色板”的实现，而不是电商产品本身。可直接打开[在线作品](https://willeastcott.github.io/splat-fashion/)查看，但应把它称为作品与参考实现。**判断：P1/P2 创作演示；可信度 B。**

### 两个新仓库尝试把 splat 变成像素化程序媒介

[SyntaxSplat](https://github.com/iamvillain/SyntaxSplat) 在浏览器里用 SDF（有符号距离场）编写场景，采样表面、烘焙光照，再经过像素化处理导出标准 PLY；它依赖 WebGL 2、浮点纹理和模块 Worker，代码为 MIT。项目给出三个可修改示例，但作者给出的生成耗时只是示例机器估计，不是跨设备 benchmark。

[Pixelart Gaussian Splat](https://github.com/cobanov/pixelart-gaussiansplat) 则基于 Three.js 与 Spark，把 glTF/GLB——包括骨骼动画——转换为硬边 surfel、限色调色板和抖动风格的 splat，要求 Node.js 20.19+ 与 WebGL 2。仓库代码为 MIT，示例生物模型来自第三方，不能随代码许可一并推定。两个项目都在本窗口创建，适合观察“直接创作 splat”是否形成新工具层，但目前都是早期演示。**判断：P2 早期工具信号；可信度 B。**

## 相关深读与行动建议

1. **PlayCanvas 项目先做旋转夹具。** 分别在 WebGPU 与 WebGL 2 下测试正负四元数、连续大角度旋转、骨骼插值和静态对照；记录当前正式版与 `ebc152e` 的像素差异，再决定是否锁主干。
2. **Budget3D 用预算曲线而不是单张好图验收。** 固定输入和随机种子，逐档记录 token 数、运行时间、峰值显存、输出 splat 数、几何完整度与视图一致性；技术报告发布前，不引用缺少条件的倍数说法。
3. **Spirula 的限边与强制退出要分开验证。** 限边测试关注内参、细节和磁盘缓存；GPU timeout 测试在可恢复的批处理环境中进行，并提前保存 checkpoint，避免把“不会永久卡住”误写成“无损恢复”。
4. **创作工具先审资产许可。** Splat Fashion 的捕获资产、Pixelart Gaussian Splat 的示例模型和各生成模型依赖不是同一许可；复用代码前分别核对。
